# PMS 前端业务与设计逻辑

## 1. 文档定位

本文档记录 PMS 前端的信息架构、页面职责、交互规则和业务展示约定，作为 Vue 页面开发与视觉回归的共同依据。

- 业务事实以后端接口和 [后端业务规范](../../pms-backend/docs/business-specification.md) 为准。
- 视觉令牌、控件尺寸和颜色语义以 [前端设计规范](frontend-design-system.md) 为准。
- 本文档描述“页面如何呈现和调用业务”，不在前端重新实现权限、数据范围或状态机。

当前产品是单企业本地部署模式。前端不展示租户切换，也不假设存在跨企业数据；企业边界由部署实例和后端数据库决定。

## 业务规则与数据不变量

下面的规则是跨页面、跨接口和跨迁移必须保持的业务事实。页面可以改变呈现方式，但不能通过前端状态、批量脚本或直接数据库修改绕过这些约束。

### 身份与账号

- 邮箱是账号的核心身份。服务端对邮箱执行 `trim + lowercase`，以 `email_normalized` 建唯一约束；登录、邀请和找回密码按该字段查询。人员列表搜索对原始邮箱做模糊匹配；顶栏搜索查项目、任务、里程碑和评论，不搜人员。
- 中文名和英文名/账号都是可选展示字段，优先显示“中文名（英文名/账号）”，两者都缺失时回退完整邮箱；姓名不能作为账号唯一键。
- 密码只保存单向哈希；Token、验证码、激活链接和重置链接属于秘密，不能进入日志、审计差异、截图或导出文件。
- 停用账号必须使现有会话失效，但不能删除项目、任务、评论、附件或审计历史。当前没有独立的启用接口；密码重置成功会把账号改回可用。

### 组织、归属与业务线

- 组织树必须单根、无环；公司总部是容器，选择器会跳过公司节点。组织编码全树唯一。业务线当前允许选到中间层，选中后可带出该节点负责人，不强制叶子。
- 组织负责人是组织节点字段；员工主归属是员工岗位关系。主归属、兼职归属、项目归属和组织负责人四者独立存储、独立审计。
- 停用前检查下属组织和有效关联；移动只校验不成环，不在移动时清点人员和项目引用。停用优先于物理删除，历史 ID 要保留以便追溯。
- 组织路径由节点 ID 实时组装，列表、详情、选择器和权限计算不得各自维护一份名称字符串。

### 授权与数据范围

- 项目读取要求“已登录且持有 `project:read`”，读取范围固定为全公司，覆盖项目、任务、节点、里程碑、评论、附件、成员和关注人；反馈中心继续使用独立的 `feedback:*` 权限。前端隐藏菜单只是体验优化，服务端才是最终边界。管理端人员、组织和审计查询本期保持既有权限码和行为。
- 项目写入分治理路径和责任路径：治理角色依据功能权限与组织范围写入；创建人/项目经理按项目责任关系拥有同等项目级权限；节点负责人和任务负责人即使没有 `project:write`，也只能有限修改自己负责的节点/任务内容。不能把功能权限、数据范围和责任关系对所有人机械地做成三重交集。
- 项目权限点至少区分 `project:read`、`project:create`、`project:write`、`project:manage`、`project:comment:write`。所有标准角色默认可以创建项目，但创建业务线仍受范围约束，`SELF` 在创建场景指本人当前有效主归属组织，不含下级。
- 数据范围支持本人、本人及下属、本组织、本组织及下级、自定义组织和全公司；计算依据当前有效主归属与组织树。
- 内置角色保持稳定，差异化需求通过自定义角色实现。角色编码用于 API 和审计，中文角色名用于界面。

### 项目交付与可恢复性

- 项目列表和详情读取同一个项目聚合；项目 ID 是任务、节点、里程碑、通知、协作和审计的对齐键。
- 创建项目时不填写项目经理；第一个节点确认时单独选择。项目创建人和项目经理是不同业务身份，但拥有相同的项目级责任权限。业务线负责人可以作为节点负责人候选，但不能覆盖项目经理；`ownerId`、成员和关注关系也不能单独产生管理权。
- 所有标准角色默认有创建权限；创建人自动成为项目成员。项目详情可以读取全部项目内容，但工作台仍只展示个人待办、个人参与项目和相关动态。
- 已删除项目对普通读取视为不存在，不进入列表、搜索、统计或普通直链；已终止项目可读但只能恢复，不能写项目内容；已完成节点必须先回滚，已终止节点必须先恢复。
- 项目终止/恢复、节点回滚等危险操作需权限和原因，并写生命周期日志。完成节点校验 kickoff 资料、负责人和该节点未完成任务。关键写操作中，反馈等对象使用乐观锁，组织/项目/任务不统一要求客户端版本号。

### 导入、审计与恢复

- 导入先解析和预览，再校验关系冲突；员工按规范化邮箱查重，组织按编码和父子顺序处理，并绑定导入任务 ID。已存在记录报错，不会静默覆盖。模板不含兼职/项目归属列。
- 提交采用全有全无事务，任一行失败则整体回滚；成功后页面不能撤销该批次。失败可下载错误行，审计记录导入任务。页面目前显示处理行数，不单独展示成功数、失败数和请求 ID。
- 操作审计至少记录操作者、资源类型与 ID、项目上下文、动作、请求 ID、时间、结果、原因和前后差异；项目终止/节点完成同时保留领域生命周期历史和跨模块审计事件。密码、Token、验证码等秘密永不落审计。审计列表只要求 `admin:audit:read`，不按项目数据范围再过滤。
- 迁移按版本和校验和顺序执行；备份恢复、故障演练和回滚都要能从日志与运行手册重放，生产禁止直接编辑业务表。

## 2. 信息架构与导航

主导航分为三个层级：

```text
工作台
研发管理
└── 项目管理
配置管理
├── 人员与权限
├── 组织架构
├── 角色管理
├── 批量导入
└── 审计日志
```

“研发管理”是业务大页签，后续可在其下扩展需求管理、测试管理、版本管理等研发协作模块；“配置管理”只承载组织、权限、角色、导入和审计等企业治理能力。新增模块应先确定所属大页签，再补充路由、权限和空态，不要把业务页面直接堆到配置管理下。

页面标题使用中文，英文仅用于产品品牌、账号标识或数据编码。导航分组使用可折叠大页签，当前路由所在分组默认展开；无权访问的配置子页签不渲染。

## 3. 路由与访问控制

当前路由职责：

| 路由 | 页面 | 访问规则 |
| --- | --- | --- |
| `/login` | 登录 | 匿名；登录成功后回到原始 `redirect` |
| `/auth/activate` | 激活账号 | 匿名，仅处理邀请令牌 |
| `/auth/reset-password` | 重置密码 | 匿名，仅处理重置令牌 |
| `/dashboard` | 工作台 | 登录用户 |
| `/projects` | 项目管理列表 | 登录用户，数据由 `project:read` 决定 |
| `/projects/:id` | 项目详情 | 登录用户，项目级权限由后端返回 |
| `/notifications` | 通知中心 | `project:read`；服务端在 SQL 中过滤删除项目通知 |
| `/admin/users` | 人员与权限 | `admin:user:read` |
| `/admin/org` | 组织架构 | `admin:org:read` |
| `/admin/roles` | 角色管理 | `admin:role:read` |
| `/admin/import` | 批量导入 | `admin:import:write` |
| `/admin/audit` | 审计日志 | `admin:audit:read` |

路由守卫只做“是否登录”和“是否显示页面”的第一层判断；接口返回的 401、403 仍由请求层和页面状态处理。按钮、表单字段和危险操作必须同时依据后端返回的 `permissions` 或用户权限点禁用/隐藏，不能仅依赖前端路由守卫。

## 4. 人员与组织展示约定

### 4.1 人员标签

所有人员选择器、项目成员、负责人、评论作者、创建人和工作台列表统一使用：

```text
中文名（English.Name）
示例：张伟（Alex.Zhang）
```

规则：

1. 邮箱是账号核心身份；中文名和英文名均为可选展示字段。优先显示 `中文名（英文名/账号）`，缺少任一姓名时显示已有姓名，姓名都缺失时回退完整邮箱。
2. 登录和密码重置只输入邮箱，服务端对邮箱执行 trim + 小写规范化；旧 `username` 仅作为兼容字段，不再作为新账号必填项。
3. 搜索可匹配中文名、英文名和邮箱；下拉选项、已选标签和只读详情必须调用共享的 `formatPersonLabel`，不得展示系统生成的兼容用户名。
4. 不在人员标签中展示数据库 ID；需要诊断时放在辅助信息或审计详情中。

### 4.2 主归属、兼职归属和组织负责人

- 人员主归属在人员管理页展示为单值；兼职/项目归属独立展示为多值。
- 组织架构节点展示组织负责人；组织负责人与员工主归属是独立关系，前端不得在编辑其中一项后自动修改另一项。
- 业务线选择器从组织树生成完整路径，跳过公司总部；当前允许选到中间层组织，选中后可带出该节点负责人。
- 组织树节点显示“负责人：统一人员标签”或“负责人：未设置”，避免只显示一个难以识别的节点名称。

## 5. 页面业务逻辑

### 5.1 工作台

工作台展示当前登录用户的工作集合，而不是全公司的静态看板：

- 我的项目：用户作为项目经理、负责人或成员参与的项目。
- 待办任务：分配给当前用户且未完成的任务，按截止日期和优先级排序。
- 近期里程碑：用户参与项目中即将到期或最近变更的里程碑。
- 最近动态：用户有权限访问的项目评论和生命周期活动。

每个模块都要有加载、空态、错误重试入口；后端没有返回某项数据时显示空态，不在页面内造一条假记录。点击卡片进入对应项目或任务详情。工作台刷新失败时保留已加载卡片，只显示失败原因。

### 5.1.1 通知中心

通知中心是顶栏铃铛的完整列表，不是工作台的扩展。页面要求 `project:read`，调用 /notifications/page 分页查询；筛选只允许全部、未读、TASK_DUE_SOON 和 TASK_OVERDUE 四种视图。筛选变化重置到第 1 页，翻页保留筛选。通知正文按纯文本插值渲染，点击后通过项目、节点或任务深链进入详情，无法定位的历史通知只展示。

提醒文案必须准确表达“触发一次”，不能写成每天催办。默认提前 7 天时，临期状态窗口为 today 至 today + 7，但只有 dueDate = today + 7 的 09:00 写入临期通知；dueDate = today 的任务不发临期。逾期只在 dueDate = today - 1 的 09:00 写入一次。新建、改期、重开不在窗口内部补发，上线首日和漏跑也不回填历史；更换负责人只影响后续扫描，旧提醒保留。

页面要同时提供加载、空态、错误重试和批量已读反馈。它不改变工作台的“我的待办 / 我参与的”范围。提醒首期只属于站内通知，不触发 Webhook、邮件或企业 IM；具体项目删除/终止过滤由后端 SQL 和项目生命周期规则保证，前端不自行猜测数据范围。

### 5.2 项目管理列表

项目列表和项目详情必须使用同一项目聚合返回的数据：

- 项目名称、编号、状态、优先级、进度、任务数和成员数来自项目聚合。
- 业务线显示组织完整路径；负责人显示组织负责人。
- 项目经理按统一人员标签显示；没有项目经理时显示“待分配”。“创建人”只在详情元信息中展示，不替代项目经理。
- 项目周期在窄列中分两行显示“开始日期”“至 结束日期”，不能让日期撑破表格。
- 表格查询参数、分页和状态筛选交给 API 层；筛选条件变化后清理过期页码并显示加载状态。

列表操作：进入详情、新建、编辑、删除。删除必须二次确认，并明确说明关联任务、里程碑和成员的影响；接口失败时保留表单和列表上下文。筛选工具栏以一个带可读标签的分组呈现，搜索、状态和查询控件使用统一高度；行操作也使用固定的内联操作组，hover/focus 只增强层级，不改变表格行高。

### 5.3 项目详情

详情页按照“项目头部 → 项目流程 → 当前节点 → 项目基本信息 → 任务看板 → 项目协作”组织。

- 项目头部展示项目状态、周期、项目经理、项目等级、优先级和项目进度；节点进度以“已完成任务数 / 当前节点任务总数”作为项目进度的辅助说明。终止/恢复等生命周期按钮只在后端 `permissions` 允许时可用。
- 流程导航使用节点顺序和状态，不把视觉选中误当成状态变更。
- 当前节点的“节点负责人”和“节点排期”同排展示；日期选择器使用中文开始日期/结束日期提示，保存前校验完整日期范围。
- 项目基本信息中，业务线选择展示完整路径，当前允许选到中间层；选中后自动带出该组织负责人作为节点负责人候选/默认值，服务端失败时保留“待分配”并提示原因。
- 项目经理、项目成员、关注人均使用统一人员选择器；已选人员只展示一份中文+英文标签。
- 任务看板按当前节点分列待办、进行中、已完成；拖拽等同于状态变更，遵守任务权限和只读状态。
- 任务卡片采用轻阴影和明确层级，标题、优先级、负责人和截止日期优先展示，里程碑/子任务数量作为上下文标签补充；hover 时显示删除入口，删除必须确认，删除按钮不影响核心信息的可读性。
- 项目协作是跨节点的公共区：里程碑、甘特、日历、成员和动态。甘特和日历汇总项目、全部节点、里程碑和有截止日期的任务，不跟当前节点看板混在一起。
- 甘特图中的节点排期条支持按天拖动：拖动条身整体平移并保持原工期，拖动左/右边缘分别调整开始/结束日期；日期始终按天对齐，并限制在当前时间轴可见范围内。只有项目进行中、节点未完成/未锁定且后端返回 `canEdit` 的节点可拖动，项目条、任务标记、里程碑和只读节点不支持拖动。
- 没有排期的可编辑节点，时间轴空白行支持按住鼠标拖动创建排期：按下日期作为开始候选，松开日期作为结束候选，反向拖动会自动规范为较早日期到较晚日期，同一天拖动生成单日排期。简单点击仍只选中节点，不会写入日期；创建排期同样按当前可见时间轴的日期范围裁剪。
- 甘特图拖动只在松开后提交，提交前使用临时预览；保存复用节点排期接口，成功后同步当前节点详情、流程节点卡片和顶部节点日期，失败恢复原日期并提示。甘特图不能通过拖动绕过权限、节点状态或项目生命周期校验。
- 甘特图工具栏提供日期宽度调节：减小/放大按钮只改变当前视图的日期列宽，不写入项目或节点日期；日期网格、月份宽度、节点条、任务/里程碑标记、今天线和拖动换算始终使用同一列宽。宽度在 14px～52px 之间按 8px 调节，组件重新打开后恢复按时间跨度计算的默认密度。
- 里程碑页签展示状态、任务进度、计划日期和编辑/删除操作；动态页签展示评论时间线，作者仍使用统一人员标签。
- 节点负责人和节点排期分别是带中文标签的分组控件；桌面端保持同排、窄屏自动堆叠，不通过压缩标签或输入框改变语义。
- 任务卡片的删除入口保留固定操作区域，只有在 hover/focus 时显现；拖拽中的卡片用透明度、虚线和阴影反馈位置变化，不改变任务状态直到服务端确认。
- 项目协作页签是同一项目对象下的同级上下文，活动页签使用统一的底部指示条、焦点环和可滚动内容区。

### 5.4 组织架构

组织架构采用可拖拽画布而不是固定缩放的静态区域：

- 画布占据内容区主要空间，右侧属性面板固定宽度；节点过多时通过平移和缩放浏览，不压缩节点到不可读。
- 节点之间必须绘制父子连接线；移动节点时先校验不能形成环，再保存父子关系。
- 画布支持缩放、平移、选中节点和属性编辑；缩放不改变节点文字最小可读字号。
- 节点显示名称、组织类型、负责人和必要的下级数量；公司、BG、中心、部门、团队、PDT 等类型使用不同但克制的图标/徽标，不重复使用同一个导航图标。
- 新增、移动、编辑、停用和删除均走后端权限；删除前提示下属组织、成员和项目引用处理规则。

### 5.5 人员、角色、导入与审计

- 人员与权限：支持邀请、状态、主归属、兼职归属、角色和停用；批量调整主归属必须明确显示影响范围。
- 角色管理：大字号显示中文角色名，小字号显示小写英文编码；数据范围使用中文名称并在下方显示英文编码说明，例如“本组织及下级组织（org_and_descendants）”。
- 批量导入：上传后先预览逐行错误，再提交；提交按钮在预览未通过或任务过期时禁用。错误报告由服务端生成并支持下载，提交按任务 ID 幂等，失败批次整体回滚。页面显示处理行数，成功后不能在本页撤销；可到审计日志查看导入任务。
- 审计日志：筛选条件、表头和动作说明使用中文，动作编码作为小字号辅助信息；支持动作、资源、项目、操作人、结果、请求 ID 和时间筛选；详情抽屉按字段展示变更前后差异，长编码允许换行，不撑破表格；before/after 只作为文本值渲染。
- 治理页面的筛选工具栏统一使用分组语义，输入、下拉和查询动作保持同一控件几何；表格行操作使用固定的操作区，避免按钮在 hover 时改变行高或挤压业务字段。
- 组织架构是一个可平移、可缩放的工作区：画布和属性面板分别拥有独立的区域语义，画布控制只改变视口，不改变组织数据；节点连接、负责人和组织类型仍由现有组织接口提供。
- 使用手册的快速开始与功能说明属于操作入口；业务规则、前端设计规范属于长期参考资料，通过单独链接进入，避免把规范正文混入功能目录或操作步骤模板。

## 6. 视觉与组件契约

实现必须复用 `frontend-design-system.md` 中的 `--pms-*` 令牌和共享样式：

- 页面背景使用冷灰，内容面板使用白色，主操作使用深蓝；危险操作使用语义红色但不整块填充。
- 顶栏 62px，侧栏 236px，内容区最大 1460px（项目详情页本地限制 1440px）；模块间距以 8/12/16/20/24/32px 为主。
- 输入框、下拉框、日期选择器和查询按钮在同一工具栏内保持统一高度（默认 36–40px）和垂直对齐。
- 标题、正文、辅助说明遵循统一字号层级；英文编码通常放在中文说明下方，以小字号、低对比度展示。
- 卡片使用细边框和轻阴影；只有弹窗、浮层和高优先级卡片使用中等阴影。卡片 hover 不改变布局高度。
- 表格表头使用浅灰背景，长字段允许换行；日期范围、组织路径和人员标签不得通过截断隐藏关键业务含义。
- 空态说明“当前没有数据”和下一步动作；加载态不能闪烁出错误的空态；接口错误提供重试。

### 6.1 Plane + Taiga 跨页实现基线

本轮视觉重构将 Plane 的对象上下文层级与 Taiga 的高密度看板反馈落到共享页面原语：顶栏/侧栏定位当前工作区，页头承载标题和主操作，工具栏集中筛选，表格或看板承载结果，行内操作保留固定区域。项目详情按“项目上下文 → 流程 → 节点 → 协作”阅读，组织架构按“可平移画布 + 独立属性面板”阅读。

所有页面共享以下约束：

- hover、focus、拖拽只改变边框、背景、阴影、非布局位移或视口，不改变行高、卡片尺寸或业务状态；危险操作仍需原有权限、确认和服务端结果。
- 组织画布的方向键、缩放和适配视图是纯视口操作；人员、负责人、归属、导入、反馈和项目状态仍由现有接口与状态机决定。
- 桌面端保持工作台密度，窄屏将工具栏和双栏区域堆叠；表格和画布只在自身容器内滚动/平移，页面不得出现无意横向溢出。
- 对标产品的品牌、项目模型和多租户假设不进入 PMS；中文业务语义、邮箱优先身份和企业治理边界保持不变。

## 7. 请求、状态与错误处理

1. API 层统一使用 axios 实例，自动附加 Bearer token 和 `X-Request-Id`（如有）。
2. 应用启动时恢复会话并调用 `/auth/me`；令牌失效时清理本地状态并跳转登录页，保留原始目标地址。
3. 列表、详情和弹窗分别管理加载/提交状态，避免一个全局 loading 锁住整页。
4. 401 表示需要重新登录，403 表示无权限，400/业务错误显示后端可读提示，500 显示重试入口和请求 ID；不要把所有错误都显示为“暂无数据”。
5. 乐观更新只用于可回滚的小范围交互；组织移动、主归属、项目生命周期、导入提交等关键操作以服务端成功响应为准。
6. 页面组件不直接拼接数据库字段或权限判断逻辑；类型和转换函数放在 `src/types`、`src/api`、`src/views/*/workflow.ts` 等约定位置。

## 8. 响应式与可访问性

- 桌面端优先保证信息密度和对齐；窄屏下侧栏转为抽屉，内容模块单列堆叠。
- 数据表格在窄屏允许容器内横向滚动，但页面本身不得出现无意的横向溢出；重要字段保持最小宽度。
- 画布在移动端仍可平移/缩放，属性面板在节点选中后以抽屉或底部面板呈现。
- 交互控件使用真实按钮、输入框和标签，提供中文 `aria-label`；仅靠颜色表达状态时必须补充文字或图标。
- 键盘焦点、hover 删除入口和弹窗确认流程必须可操作；危险操作不可只依赖 hover 才可发现。

## 9. 开发与验收清单

新增或修改页面时逐项检查：

- 是否放在正确的大页签和路由下，并配置对应后端权限？
- 是否复用统一人员标签、组织路径、状态标签和日期格式？
- 是否与项目列表/详情的同一接口字段保持一致？
- 是否覆盖加载、空态、错误、无权限、禁用和成功反馈？
- 是否使用统一控件高度、字号、间距、颜色和卡片阴影？
- 是否在桌面和窄屏检查表格、画布、弹窗、长文本和日期换行？
- 是否执行 `pnpm typecheck`、`pnpm build`，并运行相关单元测试？
- 视觉变更是否同步更新 `docs/design-qa.md`（参考图、实现状态和有意偏差）？

业务逻辑、字段或接口变化还必须同步检查后端 [业务规范](../../pms-backend/docs/business-specification.md) 和对应迁移/测试；仅视觉变更不得顺手改变接口语义。
