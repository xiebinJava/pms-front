# PMS 前端业务与设计逻辑

## 1. 文档定位

本文档记录 PMS 前端的信息架构、页面职责、交互规则和业务展示约定，作为 Vue 页面开发与视觉回归的共同依据。

- 业务事实以后端接口和 [后端业务规范](../../pms-backend/docs/business-specification.md) 为准。
- 视觉令牌、控件尺寸和颜色语义以 [前端设计规范](frontend-design-system.md) 为准。
- 本文档描述“页面如何呈现和调用业务”，不在前端重新实现权限、数据范围或状态机。

当前产品是单企业本地部署模式。前端不展示租户切换，也不假设存在跨企业数据；企业边界由部署实例和后端数据库决定。

## 2. 信息架构与导航

主导航分为三个层级：

```text
工作台
研发管理
└── 项目管理
配置管理
├── 人员与权限
├── 组织架构
├── 角色管理
├── 批量导入
└── 审计日志
```

“研发管理”是业务大页签，后续可在其下扩展需求管理、测试管理、版本管理等研发协作模块；“配置管理”只承载组织、权限、角色、导入和审计等企业治理能力。新增模块应先确定所属大页签，再补充路由、权限和空态，不要把业务页面直接堆到配置管理下。

页面标题使用中文，英文仅用于产品品牌、账号标识或数据编码。导航分组使用可折叠大页签，当前路由所在分组默认展开；无权访问的配置子页签不渲染。

## 3. 路由与访问控制

当前路由职责：

| 路由 | 页面 | 访问规则 |
| --- | --- | --- |
| `/login` | 登录 | 匿名；登录成功后回到原始 `redirect` |
| `/auth/activate` | 激活账号 | 匿名，仅处理邀请令牌 |
| `/auth/reset-password` | 重置密码 | 匿名，仅处理重置令牌 |
| `/dashboard` | 工作台 | 登录用户 |
| `/projects` | 项目管理列表 | 登录用户，数据由 `project:read` 决定 |
| `/projects/:id` | 项目详情 | 登录用户，项目级权限由后端返回 |
| `/admin/users` | 人员与权限 | `admin:user:read` |
| `/admin/org` | 组织架构 | `admin:org:read` |
| `/admin/roles` | 角色管理 | `admin:role:read` |
| `/admin/import` | 批量导入 | `admin:import:write` |
| `/admin/audit` | 审计日志 | `admin:audit:read` |

路由守卫只做“是否登录”和“是否显示页面”的第一层判断；接口返回的 401、403 仍由请求层和页面状态处理。按钮、表单字段和危险操作必须同时依据后端返回的 `permissions` 或用户权限点禁用/隐藏，不能仅依赖前端路由守卫。

## 4. 人员与组织展示约定

### 4.1 人员标签

所有人员选择器、项目成员、负责人、评论作者、创建人和工作台列表统一使用：

```text
中文名（English.Name）
示例：谢斌（Brad.Xie）
```

规则：

1. 优先使用 `nameZh` 和 `username`，缺失字段时降级为空值或“未命名用户”，不拼接两次英文名。
2. 登录只输入英文名，匹配不区分大小写；显示时保留规范化前的英文名样式。
3. 搜索可匹配中文名、英文名和邮箱；下拉选项、已选标签和只读详情必须调用共享的 `formatPersonLabel`。
4. 不在人员标签中展示数据库 ID；需要诊断时放在辅助信息或审计详情中。

### 4.2 主归属、兼职归属和组织负责人

- 人员主归属在人员管理页展示为单值；兼职/项目归属独立展示为多值。
- 组织架构节点展示组织负责人；组织负责人与员工主归属是独立关系，前端不得在编辑其中一项后自动修改另一项。
- 业务线选择器从组织树生成完整路径，支持选择到最低可用业务线；公司总部只作为容器，不作为业务线叶子选项。
- 组织树节点显示“负责人：中文名（英文名）”或“负责人：未设置”，避免只显示一个难以识别的节点名称。

## 5. 页面业务逻辑

### 5.1 工作台

工作台展示当前登录用户的工作集合，而不是全公司的静态看板：

- 我的项目：用户作为项目经理、负责人或成员参与的项目。
- 待办任务：分配给当前用户且未完成的任务，按截止日期和优先级排序。
- 近期里程碑：用户参与项目中即将到期或最近变更的里程碑。
- 最近动态：用户有权限访问的项目评论和生命周期活动。

每个模块都要有加载、空态、错误重试和“查看全部”入口；后端没有返回某项数据时显示空态，不在页面内造一条假记录。点击卡片进入对应项目或任务详情，并保留可返回的路由状态。

### 5.2 项目管理列表

项目列表和项目详情必须使用同一项目聚合返回的数据：

- 项目名称、编号、状态、优先级、进度、任务数和成员数来自项目聚合。
- 业务线显示组织完整路径；负责人显示组织负责人。
- 项目经理显示“中文名（英文名）”；没有项目经理时显示“待分配”。“创建人”只在详情元信息中展示，不替代项目经理。
- 项目周期在窄列中分两行显示“开始日期”“至 结束日期”，不能让日期撑破表格。
- 表格查询参数、分页和状态筛选交给 API 层；筛选条件变化后清理过期页码并显示加载状态。

列表操作：进入详情、新建、编辑、删除。删除必须二次确认，并明确说明关联任务、里程碑和成员的影响；接口失败时保留表单和列表上下文。

### 5.3 项目详情

详情页按照“项目头部 → 项目流程 → 当前节点 → 项目基本信息 → 任务看板 → 项目协作”组织。

- 项目头部展示项目状态、周期、项目经理、项目成员数和总体进度；终止/恢复等生命周期按钮只在后端 `permissions` 允许时可用。
- 流程导航使用节点顺序和状态，不把视觉选中误当成状态变更。
- 当前节点的“节点负责人”和“节点排期”同排展示；日期选择器使用中文开始日期/结束日期提示，保存前校验完整日期范围。
- 项目基本信息中，业务线选择支持组织树的最低业务线，并展示完整路径；选中业务线后自动带出该组织负责人作为节点负责人候选/默认值，服务端失败时保留“待分配”并提示原因。
- 项目经理、项目成员、关注人均使用统一人员选择器；已选人员只展示一份中文+英文标签。
- 任务看板按待办、进行中、已完成分列；拖拽等同于状态变更，遵守任务权限和只读状态。
- 任务卡片采用轻阴影和明确层级，hover 时显示删除入口；删除必须确认，删除按钮不影响卡片标题、负责人和截止日期的可读性。
- 里程碑页签展示状态、任务进度、计划日期和编辑/删除操作；动态页签展示评论时间线，作者仍使用统一人员标签。

### 5.4 组织架构

组织架构采用可拖拽画布而不是固定缩放的静态区域：

- 画布占据内容区主要空间，右侧属性面板固定宽度；节点过多时通过平移和缩放浏览，不压缩节点到不可读。
- 节点之间必须绘制父子连接线；移动节点时先校验不能形成环，再保存父子关系。
- 画布支持缩放、平移、选中节点和属性编辑；缩放不改变节点文字最小可读字号。
- 节点显示名称、组织类型、负责人和必要的下级数量；公司、BG、中心、部门、团队、PDT 等类型使用不同但克制的图标/徽标，不重复使用同一个导航图标。
- 新增、移动、编辑、停用和删除均走后端权限；删除前提示下属组织、成员和项目引用处理规则。

### 5.5 人员、角色、导入与审计

- 人员与权限：支持邀请、状态、主归属、兼职归属、角色和停用；批量调整主归属必须明确显示影响范围。
- 角色管理：大字号显示中文角色名，小字号显示小写英文编码；数据范围使用中文名称并在下方显示英文编码说明，例如“本组织及下级组织（org_and_descendants）”。
- 批量导入：上传后先预览逐行错误和规范化数据，再提交；提交按钮在预览未通过或任务过期时禁用。成功/失败结果可跳转审计日志。
- 审计日志：筛选条件、表头和动作说明使用中文，动作编码作为小字号辅助信息；长编码允许换行，不撑破表格。

## 6. 视觉与组件契约

实现必须复用 `frontend-design-system.md` 中的 `--pms-*` 令牌和共享样式：

- 页面背景使用冷灰，内容面板使用白色，主操作使用深蓝；危险操作使用语义红色但不整块填充。
- 顶栏约 62px，侧栏约 236px，内容区最大约 1440px；模块间距使用 8/12/16/20/24/32px 档位。
- 输入框、下拉框、日期选择器和查询按钮在同一工具栏内保持统一高度（默认 36–40px）和垂直对齐。
- 标题、正文、辅助说明遵循统一字号层级；英文编码通常放在中文说明下方，以小字号、低对比度展示。
- 卡片使用细边框和轻阴影；只有弹窗、浮层和高优先级卡片使用中等阴影。卡片 hover 不改变布局高度。
- 表格表头使用浅灰背景，长字段允许换行；日期范围、组织路径和人员标签不得通过截断隐藏关键业务含义。
- 空态说明“当前没有数据”和下一步动作；加载态不能闪烁出错误的空态；接口错误提供重试。

## 7. 请求、状态与错误处理

1. API 层统一使用 axios 实例，自动附加 Bearer token 和 `X-Request-Id`（如有）。
2. 应用启动时恢复会话并调用 `/auth/me`；令牌失效时清理本地状态并跳转登录页，保留原始目标地址。
3. 列表、详情和弹窗分别管理加载/提交状态，避免一个全局 loading 锁住整页。
4. 401 表示需要重新登录，403 表示无权限，400/业务错误显示后端可读提示，500 显示重试入口和请求 ID；不要把所有错误都显示为“暂无数据”。
5. 乐观更新只用于可回滚的小范围交互；组织移动、主归属、项目生命周期、导入提交等关键操作以服务端成功响应为准。
6. 页面组件不直接拼接数据库字段或权限判断逻辑；类型和转换函数放在 `src/types`、`src/api`、`src/views/*/workflow.ts` 等约定位置。

## 8. 响应式与可访问性

- 桌面端优先保证信息密度和对齐；窄屏下侧栏转为抽屉，内容模块单列堆叠。
- 数据表格在窄屏允许容器内横向滚动，但页面本身不得出现无意的横向溢出；重要字段保持最小宽度。
- 画布在移动端仍可平移/缩放，属性面板在节点选中后以抽屉或底部面板呈现。
- 交互控件使用真实按钮、输入框和标签，提供中文 `aria-label`；仅靠颜色表达状态时必须补充文字或图标。
- 键盘焦点、hover 删除入口和弹窗确认流程必须可操作；危险操作不可只依赖 hover 才可发现。

## 9. 开发与验收清单

新增或修改页面时逐项检查：

- 是否放在正确的大页签和路由下，并配置对应后端权限？
- 是否复用统一人员标签、组织路径、状态标签和日期格式？
- 是否与项目列表/详情的同一接口字段保持一致？
- 是否覆盖加载、空态、错误、无权限、禁用和成功反馈？
- 是否使用统一控件高度、字号、间距、颜色和卡片阴影？
- 是否在桌面和窄屏检查表格、画布、弹窗、长文本和日期换行？
- 是否执行 `pnpm typecheck`、`pnpm build`，并运行相关单元测试？
- 视觉变更是否同步更新 `design-qa.md`（参考图、实现状态和有意偏差）？

业务逻辑、字段或接口变化还必须同步检查后端 [业务规范](../../pms-backend/docs/business-specification.md) 和对应迁移/测试；仅视觉变更不得顺手改变接口语义。
