# PMS 前端设计规范

## 目标

PMS 的前端视觉统一采用冷灰工作台风格：冷灰页面背景、白色内容面板、深蓝主色、细边框、低阴影、紧凑但清晰的信息密度。规范同时约束视觉令牌、组件使用、页面布局、状态表达和响应式行为，后续新增或修改页面优先复用本规范。

## 设计系统分层

本规范不是单纯的颜色和字号清单，而是一套可以被设计、代码和测试共同消费的产品语言。所有页面按下面三层组织，越底层越稳定，越上层越贴近业务组合：

1. **基础令牌（Primitive tokens）**：保存原始色值、字号、间距、圆角、阴影和断点等可复用值，例如 `blue-600`、`space-16`、`radius-8`。基础令牌不直接决定业务语义。
2. **语义令牌（Semantic tokens）**：说明“这个值为什么存在”，例如 `--pms-primary`（主操作）、`--pms-text-muted`（次级文本）、`--pms-danger`（危险反馈）。主题、品牌或高对比度模式只需要替换这一层的映射。
3. **组件令牌与模式（Component tokens / patterns）**：将语义令牌组合成按钮、输入框、表格、面板、画布、导航和页面模板，并定义每个组件的尺寸、状态、内容和无障碍契约。

组件不能绕过语义令牌直接写颜色或间距；页面也不能复制组件内部的状态样式。新增视觉值时，先判断它属于基础令牌、语义令牌还是组件例外，并在设计评审中记录原因、使用范围和迁移影响。

## 规范阅读方式

- **设计师**先确定信息层级、任务路径和状态，再从令牌和组件中组合页面；不要先画装饰再补业务。
- **开发者**先查找现有令牌、组件和页面原语，只有确认无法复用时才新增样式；新增组件必须包含 API、状态、键盘行为和响应式说明。
- **测试和评审人员**不仅检查正常态，还要检查加载、空态、无权限、错误、冲突、禁用、窄屏、长文本和高对比度场景。
- **业务文案**以中文为主，英文仅作为品牌、账号或编码辅助信息；翻译后不应改变控件尺寸或隐藏关键含义。

## 设计原则

1. 信息优先：标题、状态、关键操作和业务数据优先于装饰。
2. 轻量分层：使用背景、边框和间距区分区域，避免重复嵌套卡片和强阴影。
3. 一致交互：按钮、表单、Tag、Tabs、表格和空状态使用统一尺寸与语义色。
4. 可读密度：桌面端保持紧凑工作台密度，移动端按单列顺序堆叠，不产生横向溢出。
5. 真实数据：没有后端字段时展示空态，不在页面中伪造业务数据。

| `--pms-primary-soft` | `#EAF2FC` | 主色浅背景 |

| `--pms-surface` | `#FFFFFF` | 内容面板 |

| `--pms-surface-strong` | `#EDF1F6` | 分段控件、禁用区域 |

### 尺寸

- 页面顶栏高度：`62px`。
- 侧边栏宽度：`236px`，移动端隐藏。
- 页面内容最大宽度：`1440px`。
- 常用间距：`8 / 12 / 16 / 20 / 24 / 32px`。
- 默认圆角：`8px`；小控件圆角 `4px`；状态 Tag 可使用 `4px`，不默认使用超大胶囊。
- 默认阴影：轻微边界阴影；只有弹窗、浮层和高优先级卡片使用中等阴影。

### 字体

使用 `Inter`、系统中文字体和 `Microsoft YaHei` 回退，整体采用紧凑工作台比例。字号只从以下档位中选择，避免页面出现随意的 14px、15px、16px 混用：

| 令牌 | 字号 | 用途 |
| --- | --- | --- |
| `--pms-font-size-caption` | `11px` | 极弱提示、表头、辅助说明 |
| `--pms-font-size-compact` | `12px` | 元信息、标签、操作链接、次级文字 |
| `--pms-font-size-body` | `13px` | 正文、表单内容、导航、看板卡片 |
| `--pms-font-size-nav` | `14px` | 主导航与配置管理分组，保证侧栏可读性 |
| `--pms-font-size-section` | `15px` | 模块标题、统计标题 |
| `--pms-font-size-title` | `20px` | 项目详情主标题、登录页标题 |
| `--pms-font-size-display` | `22px` | 列表页主标题 |

正文行高使用 `--pms-line-height-normal`（`1.45`），短标题使用 `--pms-line-height-tight`（`1.25`），长说明使用 `--pms-line-height-relaxed`（`1.6`）。标题使用 600–720 字重，正文不使用过重字重；输入控件保留 36px 高度，保证紧凑与可操作性平衡。

## 组件规范

### 页面壳层

- 顶栏使用白色背景和底部细边框，左侧品牌，中间页面标题或搜索，右侧用户信息。
- 侧边栏使用白色背景和右侧细边框，选中项使用 `--pms-primary-soft` 与 `--pms-primary`，不使用渐变色 Logo 或大面积彩色背景。
- 内容区使用 `--pms-bg`，页面模块之间使用 16–24px 间距。

### 面板与卡片

- 默认面板：白底、`1px solid var(--pms-border)`、8px 圆角、轻阴影。
- 卡片内部优先使用留白和分隔线，不在每个字段上再套卡片。
- 统计信息可使用弱背景块，但不使用强渐变。

### 按钮

- 主按钮统一使用 `.pms-primary-button`：深蓝背景、白色文字、36px 高度、13px 字号、水平内边距 14px、6px 圆角。
- 新建、完成、发布、保存等主操作必须复用该类；页面级操作、节点详情操作和公共模块工具栏不再各自定义按钮尺寸。
- 次按钮：白底、强边框、深色文字。
- 文字按钮：透明背景、主色文字，只用于次要操作。
- 危险操作使用危险色，不以纯红色填充整块区域，确认操作使用弹窗。

### 表单与只读字段

- 标签使用 12–13px 次级文字。
- 输入控件高度 36–40px，背景为白色或 `--pms-surface-muted`，边框为 `--pms-border`。
- 只读详情使用“标签 + 内容”的表单式布局；大段描述使用独立内容块。
- 缺失数据统一显示“—”“暂无数据”或对应业务空态。

### 状态与 Tag

- 状态必须使用语义色：进行中用主色，已完成用成功色，待开始用中性灰，异常用危险色。
- Tag 使用浅色背景和深色文字，避免直接使用高饱和实心色块。

### 表格、Tabs 与空状态

- 表头使用浅灰背景、辅助色文字和 11–12px 字号。
- 表格行 hover 使用 `--pms-surface-muted`，不改变布局高度。
- Tabs 使用主色下划线或浅色选中态，不同时使用多套选中表达。
- 空状态应说明当前没有数据及下一步动作，不放无关插画。

## 交互状态与反馈

每个可交互组件都必须定义完整状态，而不是只实现“正常显示”：

| 状态 | 必须表达的内容 | 实现要求 |
| --- | --- | --- |
| 默认 / Hover | 当前可操作性 | 不改变布局尺寸；hover 只增强背景、边框或阴影 |
| Focus-visible | 键盘当前位置 | 保留清晰焦点环，不能用 `outline: none` 抹掉焦点 |
| Loading | 请求正在进行 | 保留原有上下文，防止重复提交，必要时显示进度 |
| Disabled / 无权限 | 为什么不能操作 | 使用禁用样式或权限提示，不能让用户猜测 |
| Empty | 当前没有什么 | 说明“没有数据”的范围，并提供下一步动作 |
| Error / Conflict | 请求发生了什么 | 显示可读原因、请求 ID 和重试或刷新路径 |
| Success | 操作是否生效 | 使用短暂通知或状态更新，确保服务端结果已确认 |
| Danger | 可能造成的影响 | 说明对象、后果、是否可恢复和取消路径，并二次确认 |

轻量、可回滚的交互可以使用乐观更新；组织移动、主归属调整、导入提交、项目终止等关键写操作必须等待服务端成功。动画只用来说明空间关系和状态变化，时长短、可中断，并尊重 `prefers-reduced-motion`。

## 响应式与画布布局

- **桌面（≥ 1200px）**：侧栏固定在 236px，内容区域使用 `minmax(0, 1fr)`，表格和详情保持工作台密度。
- **平板（768–1199px）**：内容边距收窄，双栏模块允许变成单栏；属性面板可以变为抽屉。
- **移动（< 768px）**：侧栏转为抽屉，页面模块单列堆叠，主要操作保持可触达的 36–44px 点击区域。
- 表格、时间线和组织画布只在自己的容器内横向滚动、平移或缩放，不能让整个页面出现无意的横向滚动。
- 组织画布节点使用最小可读字号；缩放改变视口比例，不通过压缩文字来“塞下”整棵树。画布应提供平移、缩放、适配视图和键盘可达的节点入口。

## 内容、国际化与无障碍

- 中文是界面主语言；英文品牌、账号名和编码作为辅助信息，格式统一为“中文（English）”或“中文 + 小号编码”。
- 日期、数字、状态、错误和权限提示使用可读中文；英文翻译不得改变字段含义、截断唯一标识或破坏布局。
- 页面使用语义化标题层级、真实按钮、表单标签和 `aria-label`；图标按钮必须有可读名称。
- 颜色不是唯一信号：状态同时提供文字或图标；正文与背景、控件边框与背景满足 WCAG AA 对比度基线。
- 键盘可以完成导航、筛选、打开/关闭弹窗、提交和危险操作；焦点关闭弹窗后回到触发控件。
- 图片提供替代文本，视频提供字幕或文字摘要；所有演示素材、日志和工单先脱敏。

## 组件治理与版本化

新增组件或模式必须附带：适用场景、不适用场景、API/插槽、全部状态、响应式行为、无障碍说明和示例截图。变更按“令牌 → 组件 → 页面 → 文档 → 测试”顺序评审，并在 `design-qa.md` 记录：

1. 变更背景和用户问题；
2. 影响的令牌、组件和页面；
3. 有意偏差与兼容策略；
4. typecheck、build、单元测试和桌面/窄屏验收结果。

破坏性视觉变更需要版本号和迁移说明；共享组件的问题应在共享原语修复，禁止在业务页用 `!important` 或魔法值掩盖契约问题。

## 参考依据

本规范吸收成熟设计系统的共同做法，并结合 PMS 的企业管理场景落地：

- [Ant Design Design Language](https://ant.design/docs/spec/introduce/?locale=en)：企业级产品的信息架构、设计原则和组件化方法。
- [Material 3 Theming](https://developer.android.com/codelabs/m3-design-theming?hl=en)：颜色角色、字体层级、形状和可访问对比度的令牌化思路。
- [Carbon Design System — Get started](https://carbondesignsystem.com/designing/get-started/)：组件、模式、内容和治理需要共同维护。
- [Automattic Design System Foundations](https://system.automattic.design/foundations/)：基础层、令牌、布局、动效和无障碍的系统化组织方式。

## 页面改造顺序

1. 全局令牌和 Ant Design Vue 主题。
2. 应用壳层：顶栏、侧边栏、内容容器、用户菜单。
3. 项目列表：页头、统计、筛选、表格、弹窗。
4. 项目详情：项目头部、流程导航、项目资料、节点详情、协作区。
5. 登录页及其他页面。

## 开发约束

- 新增样式优先使用 CSS 变量，不直接写颜色字面量。
- 组件内只保留页面特有布局，通用视觉交给全局令牌或共享类。
- 不为了视觉引入新的业务字段；字段缺失时使用空态。
- 每次页面改动至少执行 `pnpm typecheck`、`pnpm build`，并在浏览器检查桌面和窄屏布局。
- 视觉改动完成后更新 `design-qa.md`，记录参考图、实现状态和有意偏差。
