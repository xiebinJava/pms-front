# PMS 系统使用手册

> 本手册面向企业员工、项目经理和系统管理员。页面中的“使用手册”页签与左侧系统导航保持同构，点击目录可以跳转到对应模块。

## 1. 阅读约定

- **员工**：主要使用工作台、项目管理和项目协作功能。
- **项目经理**：在项目管理中维护项目经理、成员、节点、任务和里程碑。
- **管理员**：在配置管理中维护人员、组织、角色、批量导入和审计日志。
- **邮箱为唯一登录凭据核心**：中文名、英文名是展示信息，不是登录凭据。邮箱登录不区分大小写。
- **组织负责人和员工主归属独立**：组织负责人描述“谁负责这个组织单元”；员工主归属描述“员工的主岗位归属”，两者不会互相覆盖。

## 2. 截图、GIF 和操作视频

使用手册页面每个模块都预留了媒体卡片。简单功能建议使用一张清晰截图；涉及多个步骤、层级关系或回滚的复杂功能建议放操作视频，必要时补充 GIF。

### 2.1 素材目录与命名

将素材放入前端项目的 `public/manual/` 目录，页面会以静态资源方式读取：

```text
public/manual/
├── quick-start-login.png
├── project-business-line.gif
├── organization-canvas.mp4
└── import-preview.webm
```

仓库当前已附带一组可直接预览的脱敏截图素材：`workbench.jpg`、`project-list.jpg` 和 `organization-canvas.jpg`。复杂操作的视频只有在真实录屏素材准备好后才会展示；当前版本不放置占位视频，避免把示意动画误认为实际操作。企业部署时可以继续补充自己的脱敏截图、GIF 或录屏。

素材建议使用模块前缀命名，例如 `project-*`、`organization-*`、`import-*`。截图推荐 PNG/JPG，动画推荐 GIF，视频推荐 MP4 或 WebM。视频应包含字幕或在文档中同步写出关键步骤，不要录入密码、Token、验证码或不必要的个人信息。

### 2.2 页面接入方式

`src/views/manual/index.vue` 中的 `media` 数组就是媒体清单。简单功能保留 `image` 或 `gif` 插槽；复杂功能只有在有真实录屏文件时才填写 `video` 插槽的 `src`，并可用 `poster` 指定视频封面。没有真实素材时不渲染视频卡片，只保留文字步骤，避免展示占位内容。

## 3. 快速开始

### 登录与首次使用

1. 使用管理员登记的邮箱登录，邮箱大小写不敏感。
2. 首次登录后检查右上角显示信息和账号状态。
3. 打开工作台，查看待处理任务、到期提醒和参与项目。
4. 需要修改密码时，打开右上角菜单，提交当前密码和符合策略的新密码；成功后重新登录。

中文名和英文名可以只填其中一个。没有英文名时，系统展示中文名；没有中文名时，可以用邮箱本地部分作为兜底展示。

## 4. 工作台

工作台是个人工作入口，数据只来自当前账号有权限访问的项目和任务。

### 使用方法

1. 在“工作概览”查看待处理任务、进行中任务、近 7 天到期和参与项目。
2. 在“我的任务”中优先处理高优先级或临近截止日期的任务，点击任务行进入项目详情。
3. 在“项目进展”查看项目状态、进度、业务线完整路径和项目经理。
4. 在“最近动态”查看项目留言，点击项目名称回到协作区。
5. 如果接口暂时失败，点击“刷新”；页面会保留已经成功加载的内容。

### 边界

工作台只聚合数据，不直接编辑项目、任务或里程碑。编辑请进入项目详情。

## 5. 研发管理

研发管理是交付流程的一级页签，当前包含“项目管理”，后续可扩展需求管理、测试管理和缺陷管理。它与“配置管理”边界清晰：研发管理推进交付，配置管理治理组织和权限。

## 6. 项目管理

### 6.1 项目列表

1. 点击“新建项目”创建项目。
2. 使用项目名称搜索，或按状态筛选。
3. 列表中的项目名称、业务线、项目经理、状态、优先级、进度、任务数、成员数和周期应与项目详情对应。
4. 日期较长时会分两行展示；移动端可以左右滑动查看完整字段。

### 6.2 新建与编辑项目

1. 填写项目名称、描述、优先级和项目排期。
2. 业务线按组织树逐层选择到最低层，页面展示完整的“公司 / 中心 / 部门 / 团队”路径。
3. 选择业务线后，若该组织单元已设置负责人，节点负责人会自动带出。
4. 设置项目经理、项目成员和关注人。人员统一以中文名（英文名）展示；英文名缺失时不留空白。
5. 保存后进入项目详情，继续维护流程节点、任务和里程碑。

### 6.3 项目详情

- **项目流程**：按节点推进项目阶段。
- **节点负责人**：负责当前节点执行；与组织负责人不是同一关系。
- **节点排期**：选择开始日期和结束日期，和节点负责人放在同一信息行。
- **任务看板**：待办、进行中、已完成三列；任务卡片悬停时显示删除入口，删除属于敏感操作，需谨慎确认。
- **里程碑**：维护交付目标、计划日期和任务进度。
- **成员**：添加或移除项目成员，项目经理不可被误删。
- **动态**：发布和删除项目协作留言。
- **终止项目**：使用页面顶部的按钮执行，终止后保留历史数据并写入审计日志。

## 7. 配置管理

配置管理是管理员入口，包含人员与权限、组织架构、角色管理、批量导入和审计日志。子页签会根据当前账号权限显示；看不到某个入口时先确认角色和数据范围。

## 8. 人员与权限

### 人员身份

员工记录以邮箱为核心，中文名和英文名用于展示。邮箱必须唯一，系统会归一化大小写。

### 归属关系

- **员工主归属**：员工的主要组织岗位，可以批量调整。
- **兼职/项目归属**：员工在其他组织或项目中的协作关系。
- **组织负责人**：组织单元的负责人字段，与员工主归属独立。

调整员工主归属不会自动改变组织负责人；修改组织负责人也不会批量修改员工主归属。任何调整都应在保存后刷新列表并抽查结果。

### 账号状态与角色

停用员工账号会阻止登录，但不会删除项目、任务和审计历史。为员工分配角色后，权限点和数据范围同时生效；请用目标账号验证关键页面。

## 9. 组织架构

### 画布操作

1. 在空白区域拖拽以平移画布。
2. 使用右上角加减按钮调整缩放，节点不会因窗口变窄而被强行压缩。
3. 点击组织节点，在右侧属性面板查看类型、编码、负责人、直属人员和下级组织。

### 组织维护

1. 新增组织时选择父级，填写中文名称、小写英文编码和组织类型。
2. 为部门或团队设置负责人，负责人会同时显示在节点卡片和属性面板。
3. 调整父子关系前，先确认业务线选择和数据范围不会产生越权。
4. 停用组织前，先迁移人员和项目归属。

组织架构是业务线选择和数据范围的基础，但不会直接改变员工主归属。

## 10. 角色管理

1. 创建或编辑角色时填写中文角色名称和小写英文编码。
2. 勾选权限点，例如用户读取、组织维护、角色读取、项目维护。
3. 选择数据范围，并查看页面中的中文说明：个人、本人组织及下级、全公司等。
4. 保存后在人员与权限页面分配角色，再用目标账号验证。

英文编码只用于系统识别，页面展示优先中文，英文编码以较小字号辅助说明。后端接口仍需执行 RBAC 和数据范围校验，不能只依赖前端隐藏按钮。

## 11. 批量导入

### 推荐流程

1. 下载当前版本的 Excel/CSV 模板。
2. 按模板填写组织或员工数据；员工邮箱是幂等键。
3. 上传文件并选择导入类型。
4. 查看预览，处理必填项、重复邮箱、父级组织、编码和关系冲突。
5. 下载错误行，修正后重新预览。
6. 确认无阻断错误后提交，记录导入批次。
7. 结果不确定时不要重复提交，先查询批次和审计日志；必要时执行回滚。

员工主归属和组织负责人必须使用不同字段。导入涉及组织调整、账号停用或主归属变化时，系统会记录审计日志和组织变更历史。

## 12. 审计日志

按动作、资源类型、资源 ID、操作人、请求 ID 和时间范围筛选日志。打开“查看差异”对照变更前后值，定位组织、人员、角色和导入问题。

反馈问题时请提供页面 URL、操作步骤、发生时间和请求 ID；截图或视频必须脱敏。审计日志不应包含密码、Token 或验证码。

## 13. 常见问题

### 登录出现 401 或 500

记录时间和请求 ID，刷新后重新登录；仍失败时交给管理员查看后端日志与数据库连接。不要在浏览器中反复提交未知结果的请求。

### 左侧入口无法点击或消失

配置管理子页签按权限显示。检查当前账号是否拥有对应读取或写入权限，并确认账号没有被停用。

### 人员主归属仍显示公司总部

确认调整的是“员工主归属”而不是“组织负责人”，保存后刷新人员列表。两套关系独立，不会因为设置组织负责人而自动同步。

### 业务线负责人没有自动带出

确认项目选择的是最低层业务线，并检查组织架构中该节点是否已设置负责人。

### 项目列表和详情不一致

先刷新并核对同一个项目 ID，再查看接口响应和审计日志。项目列表与详情应使用同一项目记录。

### 导入结果不确定

不要重复提交；先查看导入批次、错误下载和审计日志，必要时按运行手册执行回滚。

## 14. 安全提醒

- 生产环境使用强 JWT 密钥、HTTPS、受限 CORS 和企业 SMTP。
- 禁止使用默认密码；密码修改后应重新登录。
- 不在截图、GIF、视频、日志或工单中暴露密码、Token、验证码和完整敏感邮箱。
- 敏感操作完成后检查审计日志，数据库问题先保留证据再按恢复流程处理。
