# PMS 系统使用手册

> 本手册面向企业员工、项目经理和系统管理员。应用里的「使用手册」页签与左侧导航同构，点击目录可以跳到对应模块。
>
> **当前基线**：PMS v1.0.0，运行时使用 MySQL 8，数据库迁移为 V1–V41。本页包含 13 个功能模块；业务规则和前端设计规范通过「文档中心」进入独立页面。正文滚动时目录会自动高亮并同步 URL，点击目录仍可直接定位。

## 1. 阅读约定

- **员工**：主要使用工作台、项目列表、项目详情和顶栏搜索 / 通知。
- **项目经理**：在项目详情维护资料、节点、任务、迭代计划、成员和关注人。
- **管理员**：在配置管理维护人员、组织、角色、批量导入和审计日志。
- **邮箱为唯一登录凭据核心**：中文名、英文名只用于展示。邮箱登录不区分大小写。
- **组织负责人和员工主归属独立**：组织负责人描述“谁负责这个组织单元”；员工主归属描述“员工的主岗位”，两者不会互相覆盖。

## 3. 快速开始

1. 使用管理员邀请时登记的邮箱登录。邮箱不区分大小写。
2. 本机默认是邮箱加密码。管理员启用 OIDC 或 LDAP 后，登录页才会出现对应按钮。
3. 登录后看右上角：姓名、中文 / English、搜索框和通知铃。
4. 顶栏搜索至少输入两个字，可在权限范围内查找项目、任务和评论。
5. 通知铃收录任务指派、任务/项目评论（关注人也会收到项目评论）、节点完成/回滚，以及任务临期/逾期提醒。点击“查看全部通知”进入通知中心；提醒只会打开当前账号可读的项目、节点或任务。
6. 修改密码成功后必须重新登录。重启后端也会让已有登录失效。

中文名和英文名可以只填一个。没有英文名时展示中文名；没有中文名和英文名时用完整邮箱兜底。

### 3.1 按角色看

- **普通员工**：登录后能看到工作台、研发管理、反馈中心和使用手册；有搜索和通知铃；看不到配置管理。
- **部门负责人 / 业务线负责人**：还会看到配置管理，但只有人员和组织结构。
- **组织管理员**：配置管理里能看到人员、组织、角色、导入和审计；角色页只能看。
- **超级管理员**：配置管理全部入口可见；`system_role=1` 还会绕过功能权限和数据范围。

## 4. 工作台

工作台是个人入口。数据来自 `GET /workbench`，只包含当前账号有权限看到的任务、项目和动态。

1. 工作概览：待处理、进行中、近 7 天到期、参与项目。
2. 我的任务：点击任务行打开所属项目，并直接进入该任务详情。
3. 项目进展：状态、进度、业务线路径、项目经理。
4. 最近动态：点击项目名称回到该项目的动态页签。
5. 部分接口失败时点刷新；已加载成功的内容会保留。

工作台不直接改项目、任务或迭代计划。编辑请进入项目详情。

### 4.1 按角色看

- 工作台只统计指派给自己的任务，以及自己作为成员、创建人、项目经理或项目负责人参与的项目。
- 部门负责人的数据范围是本组织及下级，但工作台不会因此列出部门里别人的项目或任务。
- 项目管理员在项目列表能看全公司，工作台数字仍不是全公司总量。

## 4.2 通知中心

通知中心是顶部铃铛背后的完整站内通知列表，要求当前账号持有 project:read。它不改变工作台的个人待办范围，也不把工作台变成全公司任务看板。

1. 点击顶部铃铛 → “查看全部通知”，进入通知中心；也可以从 /notifications 直接打开。
2. 用“全部、未读、临期、逾期”筛选。四种筛选互斥，切换筛选会回到第 1 页，翻页保留当前筛选。
3. 点击通知打开关联的项目、节点或任务；没有项目上下文的历史通知只展示，不强行跳转。
4. 点击“全部标为已读”后，服务端确认当前账号的通知已读，页面再更新状态。

任务提醒的实际触发规则：

- 临期状态窗口是今天至未来第 7 天（默认含今天共 8 个自然日），但通知只在进入窗口外沿当天，即 dueDate = today + 7 的 09:00 写入一次；到期当天不发临期。
- 逾期通知只在 dueDate = today - 1 的 09:00 写入一次。上线第一天不回填更早的历史逾期，作业停机错过触发日也不补发。
- 新建、改期或重开任务只有在当天恰好落在上述触发边界时才可能发提醒；改到窗口内部、改成今天或窗口内其他日期不补发。
- 只通知当前任务负责人；没有负责人、已完成任务、停用员工和已删除项目中的任务不会产生新提醒。更换负责人不会收回旧记录，也不改旧记录的已读状态。
- 提醒第一期只写入站内通知，不发送邮件、飞书、企业微信或出站 Webhook。重复扫描由数据库去重，不会重复增加通知。
- 终止项目仍可读，历史提醒可以打开；已删除项目按不存在处理，不进入通知列表、未读数或普通深链。

通知页面会展示加载、空态和错误重试。提醒作业默认关闭，只有项目权限收口完成且 SQL 可读性过滤验收通过后，运维才可以显式开启。作业按配置时区（默认 Asia/Shanghai）计算日期；本期工作台“近 7 天到期”仍按 JVM 默认时区，午夜附近可能与通知日期相差一天。

## 5. 研发管理

左侧一级页签「研发管理」下面，**本版本只有「项目管理」**。没有需求管理、测试管理或缺陷管理入口。

收起一级页签只是收起菜单，当前页面不会丢。研发管理面向交付，配置管理面向组织与权限，不要混用。

本版本还包含组织变更历史、导入失败状态和错误行下载能力；它们分别在组织架构和批量导入模块中说明。需求管理、测试管理和缺陷管理仍未上线。

「研发管理 → 项目管理」入口对所有已登录账号可见，前端不按权限隐藏。没有 `project:read` 时接口会拒绝；内置角色都带这个权限。任何角色都看不到需求、测试或缺陷入口，因为功能未上线。

## 6. 项目管理

### 6.1 项目列表

1. 打开页面时，项目经理默认进入「我负责的」，具备 `project:manage` 的人默认进入「公司组合」；需要翻当前可见范围内的全量时再点「全部」。
2. 公司组合和我负责的视图会显示进行中、已逾期、未指定项目经理、节点逾期四张摘要卡，点击可作为筛选。
3. 可用项目名称、状态、业务线（含下级）、项目经理、项目等级和当前节点筛选。
4. 列表展示业务线路径、项目经理、项目等级、当前节点、状态、优先级、进度、任务数、成员数和两行周期。
5. 这些字段与项目详情读同一条项目记录。
6. 移动端表格可以左右滑动。

### 6.2 新建项目

列表上的「新建项目」先填名称、描述、优先级和项目排期。新建项目的项目等级默认为常规项目（C），后续可在启动节点的项目基本信息中调整。创建项目不需要填写项目经理；创建人会自动成为项目成员和项目责任人。业务线、成员和关注人在启动节点的资料区补全，第一个节点确认时再单独选择项目经理。

业务线可以选择中间层，只要该组织有人承接。选择业务线只保存组织路径，不会改节点负责人。组织负责人不会自动变成项目经理，也不会因此获得项目管理权限。

### 6.3 项目详情

- **项目流程**：按节点推进。完成当前节点会解锁下一节点；回滚需要原因，之后的节点回到未开始。
- **节点负责人 / 节点排期**：和当前节点放在同一行。节点负责人不是组织负责人。创建项目后，第一个节点会自动带出项目创建人；指定项目经理后，后面还没有人手动改过的节点会自动带出项目经理。人员选择框可以搜索全公司已激活账号；选中后会自动加入项目成员。
- **项目基本信息**：优先级表示当前紧急程度；项目等级表示项目重要性，分为战略项目（S）、关键项目（A）、重要项目（B）、常规项目（C）。新建项目默认常规项目（C），修改项目等级属于项目资料修改。
- **需求澄清与范围基线**：在该节点维护纳入/不纳入范围和需求清单；项目目标与节点交付结果沿用前一“项目立项与启动”节点，不在本节点重复填写。需求清单把已澄清内容拆成带编号、类型、优先级和验收标准的可追踪条目，服务后续方案、开发和验收。只有需求状态为“已确认”时才能从需求行创建任务，任务会自动带入需求编号，需求行回显“已完成/任务总数”；需求确认仍是人工操作，不会被任务完成状态替代。
- **需求基线确认**：完成该节点前，至少保留一条纳入范围项、至少添加一条需求，并将需求清单全部确认。编辑内容会自动保存；确认后的当前可编辑节点仍可直接修改，保存后基线会回到待确认状态，需求状态仍需人工确认；如果节点已经完成，需先回滚节点再编辑。多人同时编辑发生版本冲突时，需刷新页面后继续编辑。
- **方案设计、评审与决策**：需求范围基线确认后，进入该节点维护一个方案包，只填写产品方案和技术方案。方案包字段会自动保存，两个方案字段填写完整且上游基线已确认后自动提交。提交后按固定的业务/产品、技术、测试/发布三类评审逐项完成；节点负责人可为每类评审选择人员（选中后自动加入项目成员），只有指定评审人或管理员可以完成评审。三类评审全部通过后，填写通过、条件通过或退回修改；条件通过时还要填写通过条件，决策字段同样自动保存。完成决策确认后，修改已确认内容会自动使相关确认失效，并按原规则重新评审/确认；如果节点已经完成，需先回滚节点再编辑。该节点只有方案包已提交、三类评审全部通过且决策已确认后，才能完成节点。
- **其他节点工作台**：计划、资源与风险基线、业务验收与缺陷闭环、发布决策与运营交接、价值验证与项目复盘等节点的可编辑字段会自动保存；开发测试与项目控制中的专题和故事在填写有效内容后也会自动保存。原有完整性校验、评审/验收/决策等人工确认和权限规则保持不变。已确认内容在当前可编辑节点中可直接修改，保存后自动重新校验；已完成节点需先回滚，节点回滚是唯一的生命周期解锁入口。
- **任务看板**：只显示当前节点的待办、进行中、已完成。点开任务可管理子任务、任务评论和图片/PDF 附件（单文件不超过 5MB）。子任务可以选择状态和填写截止日期，也可以删除；截止日期不是必填项。已完成的父任务不能新增子任务；附件上传者可以删除自己的附件，其他删除权限以服务端返回的任务能力为准。
- **子任务规则**：父任务完成时，系统会自动完成全部子任务；没有截止日期的子任务会补成父任务完成当天日期，已有截止日期不会被覆盖。父任务完成后，不能直接把子任务改回待办或进行中，需要先回退父任务。
- **项目协作**：页签依次是甘特、日历、成员、动态；迭代计划在“计划、资源与风险基线”节点维护，开发专题和故事可按需关联迭代计划。
- **甘特 / 日历**：甘特图纵轴是有工期的节点，项目、节点和迭代计划使用排期展示，有截止日期的任务落在当天。对有排期且具备节点编辑权限的进行中节点，可以拖动条身整体调整排期，也可以拖动左右边缘分别调整开始/结束日期；没有排期但具备编辑权限的进行中节点，可以在时间轴空白行按住鼠标拖动创建排期。创建时按下和松开的位置分别确定日期，反向拖动会自动规范日期，同一天会生成单日排期；普通点击只选中节点。日期按天对齐，不能拖动项目条、任务标记、迭代计划或只读节点。日历仍是只读视图，本期没有任务依赖。
- **甘特排期保存**：拖动松开后才提交服务端；保存成功会同步节点详情、流程卡片和顶部节点日期，保存失败会恢复原日期。拖动不能绕过项目权限、节点状态或项目终止/锁定规则；没有可编辑节点时，仍可通过当前节点的日期选择器设置初始排期。甘特工具栏的「日期宽度」可用减号/加号调整当前视图的日期列宽（14px～52px，每次 8px），只影响显示密度，不修改项目或节点日期；重新打开甘特图后恢复默认密度。
- **关注人**：会收到项目评论；节点完成或回滚时也会收到站内通知。
- **终止 / 恢复**：页顶操作，必须填写原因，并写入审计日志。项目创建人、项目经理、拥有 `project:manage` 且范围命中的治理角色，或 `system_role=1` 可以操作；部门负责人 / 业务线负责人第一期没有角色级 `project:manage`。

### 6.4 按角色看

- **普通员工**：只要有 `project:read`，可以查看全公司项目及其任务、节点、评论、附件、成员和关注人；所有标准员工也有 `project:create`，可以在本人主归属组织创建项目。普通员工没有角色级 `project:write`，但被指定为任务/节点负责人后，可以有限修改自己的任务/节点内容和上传自己任务的附件；不能修改项目资料、结构、他人任务或成员。
- **部门负责人 / 业务线负责人**：查看全公司项目；可以在本人组织及下级创建项目，并在该范围内执行常规项目写入。第一期没有角色级 `project:manage`，终止、恢复、删除和成员治理仍需项目责任人或治理角色。
- **项目管理员**：可以查看、创建和治理全公司项目；拥有 `project:manage`，不需要是项目创建人或项目经理。
- **组织管理员**：可以查看全公司项目，并在本人组织及下级创建、常规修改和治理项目。
- **项目经理角色**：可以查看全公司项目；创建权限按本人主归属组织；对自己创建或担任项目经理的项目拥有与项目创建人相同的项目级权限。

## 7. 配置管理

配置管理包含人员与权限、组织架构、角色管理、批量导入、审计日志。子页签按当前账号权限显示；看不到入口时先核对角色和数据范围。

### 7.1 按角色看

- **普通员工 / 项目经理 / 项目管理员**：不出现配置管理。
- **部门负责人 / 业务线负责人**：只出现人员和组织结构，且只能读。
- **组织管理员**：五个子入口都在；角色页只能看。
- **超级管理员**：五个子入口都在，角色页可以写自定义角色。

## 8. 人员与权限

1. 用「邀请员工」创建账号，必填邮箱，中文名和英文名可选。初始角色从角色管理的启用角色里选。保存后复制激活链接。
2. 「归属」里主归属必须唯一；兼职/项目归属可以有多条，不会覆盖主归属。
3. 「角色」添加或移除角色。实际可见范围还取决于数据范围。
4. 停用会立刻结束登录会话，但保留项目历史和审计记录。

改员工主归属不会自动改组织负责人，反之亦然。

### 8.1 按角色看

- **部门负责人 / 业务线负责人**：能打开人员列表。当前实现不按组织再过滤，能看到全公司人员。没有 `admin:user:write`，邀请、改归属、分配角色、停用会被接口拒绝；这些按钮目前仍会显示。
- **组织管理员 / 超级管理员**：可以邀请、改归属、分配角色、停用。不能停用最后一名 `system_role=1` 账号，也不能移除最后一名 `SUPER_ADMIN`。
- **普通员工 / 项目经理 / 项目管理员**：进不了这个页面。

## 9. 组织架构

1. 按住空白区域拖拽平移。右上角可以缩放、回到 100%，或点「适配」把整棵树放进视口。
2. 点击节点查看编码、类型、负责人、直属人数。
3. 新增时先选上级（不选则在顶层），再填编码、名称和类型。
4. 指定负责人只改组织字段，不会改该员工的主归属。
5. 根组织不能停用。停用前先迁移人员和项目归属。

有 `admin:org:read` 就能看到整棵组织树，当前不会按「本组织及下级」裁剪画布。写操作只看 `admin:org:write`。被设为组织负责人，不等于拥有部门负责人角色。

### 9.1 按角色看

- **部门负责人 / 业务线负责人**：能看画布，不能新增、移动、停用或改负责人。
- **组织管理员 / 超级管理员**：可以写组织树；指定负责人只改组织字段。

## 10. 角色管理

1. 填写中文名称和编码。编码保存时转成大写，页面用小写展示。
2. 勾选权限点：人员、组织、角色、导入、审计，以及项目的读、建、常规写、治理、评论。
3. 数据范围：仅本人、本人及下属、本组织、本组织及下级、自定义组织、全公司。选自定义时还要指定组织。
4. 内置角色不能删除。分配后用目标账号验证页面和按钮。

不要靠隐藏前端按钮当鉴权。接口仍会校验权限点和数据范围。

手册里说的「人员读」「组织读」，意思是打开某个页面后能不能改东西：**读=能打开看，写=能改数据**。

- **人员读**：能打开「人员与权限」看名单。现在不按组织再过滤，部门负责人也能看到其他部门的人。
- **人员写**：能邀请、改归属、给别人加角色、停用。部门负责人默认没有。
- **组织读**：能打开组织画布看树和负责人。
- **组织写**：能新增、拖动、停用组织，改负责人。部门负责人默认没有，这些按钮会藏起来。
- **角色读 / 写**：能打开角色列表；写才能新建自定义角色并勾选能力。组织管理员只有读。
- **项目读**（`project:read`）：能看全公司项目及全部项目内容，包括任务、节点、迭代计划、评论、附件、成员和关注人。反馈中心使用独立的 `feedback:*` 权限，不会因为能看项目而看到反馈工单。
- **项目建**（`project:create`）：能创建项目。所有标准角色默认拥有；创建时不填项目经理，业务线仍受创建数据范围限制，`SELF` 指本人当前有效主归属组织。
- **项目常规写**（`project:write`）：能在角色数据范围内修改项目资料、节点、任务和常规协作数据。创建人和项目经理也可按责任关系操作自己的项目；任务/节点负责人即使没有该权限，也可有限修改自己负责的内容。
- **项目治理**（`project:manage`）：能管理成员、关注人、项目经理、任务/节点结构，以及终止、恢复、删除。项目管理员是全公司治理；组织管理员按本人组织及下级治理；项目创建人和项目经理按项目责任关系治理。
- **项目评论**（`project:comment:write`）：能在可写的进行中项目发布评论；作者删除自己的评论仍按该权限判断，删除他人评论需要项目治理权限。本期没有评论编辑接口。
- **反馈读 / 写 / 管理**：读写是提交并看自己的单；管理是分派和改状态。默认只有组织管理员和超级管理员能管理。

### 10.1 角色能力矩阵

| 角色 | 编码 | 项目能力 | 项目数据范围 |
| --- | --- | --- | --- |
| 超级管理员 | `super_admin` | 系统管理员全局绕过；项目全量读/建/写/治理/评论 | 全局绕过 |
| 项目管理员 | `project_admin` | 项目全量读/建/写/治理/评论 | 全公司 |
| 组织管理员 | `org_admin` | 项目全量读；本人组织及下级建/写/治理；全公司评论 | 读全公司，写/治理本组织及下级 |
| 业务线负责人 | `business_owner` | 项目全量读；本人组织及下级建/写；全公司评论；第一期无治理 | 读全公司，建/写本组织及下级 |
| 部门负责人 | `dept_manager` | 同业务线负责人 | 读全公司，建/写本组织及下级 |
| 项目经理 | `project_manager` | 项目全量读/建/评论；自己创建或担任项目经理的项目可治理；责任项目可常规写 | 读全公司；创建按本人主归属；写/治理按责任关系 |
| 普通员工 | `member` | 项目全量读/建/评论；本人任务/节点有限写；无角色级常规写和治理 | 读全公司；创建按本人主归属 |

### 10.2 按角色看

- **如果我是部门负责人**：日常就是能看全公司项目、在本部门及下级建项目和做常规写入、能提反馈。人员页能翻名单但不能邀请；组织画布能看树但不能拖。第一期不是项目治理角色，不能因为部门负责人身份终止、恢复、删除或管理任意项目成员；项目创建人/经理或治理角色可以做这些事。
- **如果我是组织管理员**：人员可以邀请和改归属，组织树可以改，Excel 可以导入，审计可以查。角色页能打开看，但不能改勾选。
- **如果我是普通员工**：进不了角色管理。项目可以看全公司并查看全部项目内容，也可以创建项目；如果被指派为节点或任务负责人，还能有限修改自己负责的内容，但不能改项目资料、结构、他人任务或成员。反馈可以提交。
- **如果我是超级管理员**：能新建自定义角色。系统自带角色不能删、不能改勾选，只能改名称。

管理员调整角色后，应使用目标账号分别验证“能看到什么”和“能修改什么”，并在审计日志中确认变更。后端接口是最终鉴权边界，前端隐藏菜单不能扩大权限。

## 11. 批量导入

1. 先选组织或员工，再下载当前模板。
2. 上传 `.csv` 或 `.xlsx`。页面不接收 `.xls`。
3. 预览校验。有错误先下载错误行，改完再上传。
4. 错误为零后再提交。结果未知时不要连点两次。

员工邮箱是幂等键。主归属和组织负责人是不同字段。

导入提交采用全有全无事务；失败批次会自动回滚，不会留下半批数据。提交成功后如需修正，走人员页、组织页，或按运行手册处理。组织调整、停用账号、主归属变化和导入结果都会进入审计日志。

只有组织管理员和超级管理员默认有 `admin:import:write`。部门负责人看不到这个入口。

## 12. 审计日志

可按动作、资源类型、资源 ID、项目 ID、操作人 ID、执行结果、请求 ID 和时间筛选。时间结束值按左闭右开处理，便于按天或按批次连续查询。

点击「详情」打开审计抽屉，按字段对照变更前后值，同时查看项目、操作人、结果、原因和请求 ID。已删除的项目/人员仍保留历史 ID，不会因为删除而改写审计记录。反馈问题时带上页面 URL、操作时间和请求 ID。不要把密码或 Token 写进工单。

只有具备 `admin:audit:read` 的账号可以打开审计页；`project:read` 不会自动获得审计权限。当前列表不按项目数据范围过滤，有权限就能看全量操作审计。部门负责人看不到这个入口，除非另行授予审计权限。

## 13. 反馈中心

反馈中心用于跨项目收集问题、建议和体验反馈，与项目评论分开。所有提交人必须先登录；反馈可以独立提交，也可以关联项目、任务或节点。

1. 点击左侧「反馈中心」→「提交反馈」，填写标题、详细内容、类型和优先级；必要时补充关联项目、来源模块和页面地址。
2. 提交后记录工单号。反馈会进入「待初步处理」，列表支持按编号、类型、优先级和状态筛选。
3. 打开反馈详情查看当前负责人、项目上下文和处理记录。具备管理权限的人员可在抽屉中分派负责人、调整优先级、填写处理说明并推进状态。
4. 处理流程为「待初步处理 → 已分派 → 处理中 → 待确认 → 已解决 → 已关闭」。拒绝、重复反馈和无法复现必须填写处理说明。
5. 如果处理结果仍需继续跟进，提交人或管理员可对已解决、已关闭或异常反馈执行「重新打开」。

反馈标题、正文和处理说明不得包含密码、Token、验证码或未经脱敏的个人信息。提交和每次处理变更都会留下反馈历史与操作审计。

### 13.1 按角色看

- **普通员工 / 项目经理 / 项目管理员 / 部门负责人 / 业务线负责人**：能提交并只看自己的工单，也能重开自己的工单。没有分诊控件。
- **组织管理员**：可按本组织及下级处理工单。
- **超级管理员**：可处理全量反馈。

## 14. 常见问题

### 登录失败或突然回到登录页

提示「无法连接后端服务」表示本机后端没在跑或代理连不上。提示「邮箱或密码错误」才是账号问题。突然被踢回登录页通常是会话过期或后端刚重启。仍失败时把时间和请求 ID 交给管理员查日志。

### 左侧入口不见或按钮不可用

配置管理子页签按权限隐藏。先确认角色、数据范围和账号是否被停用。

### 人员主归属没有按预期变化

确认改的是员工主归属，不是组织负责人。保存后刷新列表。

### 业务线选不中

中间层组织也可以被选中，公司总部会被跳过。

### 搜索没有结果

至少输入两个字。搜索只返回当前账号有权看到的项目、任务和评论。

### 项目列表和详情不一致

先刷新并核对该项目 ID，再看审计日志。

### 导入结果不确定

不要再点提交。先下载服务端错误报告并修正原文件；如果提交已经失败，系统会自动回滚本批次。已成功提交的批次不需要重复提交，后续修正走人员或组织页。

## 15. 安全提醒

- 生产环境使用强 JWT 密钥、HTTPS、受限 CORS 和企业邮件。
- 不要使用默认密码；改密后重新登录。
- 截图、GIF、视频、日志和工单里不要出现密码、Token、验证码。
- 敏感操作完成后检查审计日志。数据库问题先留证据，再按恢复流程处理。
