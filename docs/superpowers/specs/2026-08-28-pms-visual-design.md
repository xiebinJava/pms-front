# PMS 视觉系统迁移设计

## 1. 背景与目标

PMS 当前已经具备项目、组织、权限、导入、审计和账号等业务能力，但页面仍以 Ant Design Vue 默认组件形态为主，与外部设计参考前端的开放式内容布局、密度、边界和响应式行为不一致。本次迁移的目标是：保留已验收的业务逻辑、接口和路由，将外部设计参考前端的视觉规范完整落到 PMS 的应用壳、通用控件和业务页面中。

验收目标：

- 桌面端在 1440px 左右视口下使用 62px 顶栏、236px 侧栏和最大 1460px 内容区。
- 页面背景、面板、边框、阴影、圆角、按钮、表格、弹窗和状态标签统一使用 PMS 视觉令牌。
- 业务页面不再依赖 Ant Design 默认的间距、字体和颜色作为最终表现。
- 移动端导航变为抽屉式，表格可横向滚动，组织画布保持可拖拽和缩放，不发生挤压变形。
- 登录、项目管理、项目详情、人员、组织、角色、导入和审计核心交互保持可用。

## 3. 应用壳与组件边界

### 3.1 应用壳

`src/layout/Index.vue` 负责顶栏、侧栏、移动端导航、用户菜单和内容出口。视觉结构迁移为：

- 顶栏 sticky，62px 高，白色背景和底部边框。
- 品牌区保留 PMS 的 P 标识和 “PMS / Project Management” 文案。
- 左侧导航宽 236px，分组标题使用弱文字，当前项使用主色浅底，无右侧高亮线。
- 主区域使用 `width: min(1460px, 100%)`，桌面端内边距 31px 34px 64px。
- 760px 以下侧栏变为固定抽屉，顶栏显示菜单按钮，主区内边距收缩为 18px。

### 3.2 通用视觉组件

在 `src/components` 下新增轻量原语，内部仍可组合 Ant Design Vue 的可访问行为：

- `PmsPageHeader`：标题、说明、右侧主操作。
- `PmsButton`：primary / secondary / text / danger 状态。
- `PmsPanel`：统一面板边界和阴影。
- `PmsTable`：表头、行高、横向滚动和空状态。
- `PmsFilterBar`：搜索、筛选、重置布局。
- `PmsStatus`：成功、进行中、待处理、停用等语义状态。
- `PmsModal`：sticky 标题栏、统一动作区、移动端宽度。
- `PmsPersonSelect`：人员统一标签（中文名（英文名）→已有姓名→邮箱）展示和统一下拉样式。

已有业务组件优先通过这些原语和全局样式迁移，不改变 API 调用和领域状态。

## 4. 页面迁移顺序

1. 登录、激活、重置密码：统一认证页背景、品牌头、表单控件和错误提示。
2. 应用壳与导航：先替换全局布局，确保所有页面获得统一基线。
3. 项目列表：迁移页面头、筛选栏、表格、分页、操作链接和新建/编辑弹窗。
4. 项目详情：迁移面板分层、流程节点、人员选择、节点排期、业务线、任务看板和删除悬停态。
5. 人员与权限：迁移组织筛选、人员表格、人员标签和抽屉/弹窗。
6. 组织架构：迁移全屏画布、缩放工具、连接线、节点负责人和属性面板。
7. 角色、批量导入、审计：统一筛选、表格、步骤条、差异展开和反馈状态。

每个页面迁移完成后，必须先完成类型检查、页面级 Node 用例和浏览器截图检查，再进入下一页。

## 5. 数据与交互约束

- 不修改现有 API 契约、权限判断、路由名称和数据模型，除非视觉迁移暴露明确的显示缺陷。
- 人员展示按 `中文名（英文名）→已有姓名→邮箱` 回退；账号只在需要识别时单独展示，登录使用邮箱。
- 组织负责人和员工主归属保持两套独立关系。
- 项目列表与项目详情继续使用后端统一返回的业务线、组织路径、负责人和进度摘要。
- 组织画布使用可拖拽 viewport + 可缩放 stage；节点尺寸不随窗口强行压缩。
- 所有破坏性动作保留确认反馈；删除、停用、终止等危险动作使用危险色和清晰文案。

## 6. 验证策略

- 自动验证：`pnpm typecheck`、`pnpm build`、`node --test` 现有全部用例。
- 视觉验证：使用浏览器在 1440×900、当前开发视口和 390×844 三种尺寸检查顶栏、侧栏、标题区、表格、弹窗和画布。
- 核心流程：登录校验 → 项目列表筛选/进入详情 → 业务线选择（不改节点负责人） → 节点排期 → 任务删除 → 组织拖拽/缩放 → 角色编辑 → 导入预览 → 审计分页。
- 每期记录至少五个具体对照点（布局、字体、色彩、容器边界、响应式或交互）和修复结果；任何剩余差异必须标注为有意偏差。

## 7. 非目标

- 不迁移 外部设计参考前端 的业务页面、接口、登录方式或品牌资产。
- 不在本期引入新的 UI 框架，不为视觉迁移重写 Vue 路由和 Pinia 状态。
- 不以静态截图替换真实页面，不牺牲表格、画布、弹窗和表单的交互能力。

## 身份规则补充（2026-08-31）

本补充覆盖本文件早期对“中文名（英文名）必备”和英文名登录的描述：邮箱是账号核心身份，登录/重置密码使用不区分大小写的归一化邮箱；中文名、英文名均可选，人员标签按“中文名（英文名）→已有姓名→邮箱”回退。历史 `username` 仅保留为兼容字段，组织负责人、员工主归属和项目归属关系不受影响。
