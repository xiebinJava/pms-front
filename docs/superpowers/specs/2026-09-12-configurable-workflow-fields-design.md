# 可配置流程节点字段设计

## 背景与目标

当前工作流模板已支持项目类型、默认模板、顺序节点、可排序的节点、可复用业务工作台，以及两种字段定义。但项目资料字段单独保存在 `projectBasicInfoFields` 中，节点自定义字段保存在 `fields` 中；项目详情页又以专用区块渲染前者、以通用字段面板渲染后者。这使“项目立项与启动”的表单项不能像文本框、单选框、人员选择器一样单独配置。

本次将字段配置统一为可独立显示、隐藏、设必填、排序、选择控件类型及设置选项的字段；把当前业务工作台纳入同一节点内容排序；在流程配置页提供可视化拖放和编辑。项目类型默认模板和创建项目时允许手动切换的现有行为继续保留。

## 方案选择

1. **推荐：统一字段定义并保留旧结构适配。** 新版定义用一个字段列表表示原生项目字段和节点自定义字段；原生字段带显式绑定，不复制数据；节点内容顺序引用表单字段区或现有业务工作台。旧 schema 仍可运行，编辑器加载旧定义时转换为新 schema，另存草稿后再发布。改动覆盖前后端，但边界清晰、兼容性最好。
2. **保留两套字段定义，只重做 UI。** 实现较快，但项目字段和自定义字段仍使用不同校验、排序和渲染规则，后续新增组件还会重复维护，不建议。
3. **所有值复制到节点自定义字段表。** UI 最统一，但会产生项目资料与节点副本的同步冲突、权限分叉和数据迁移风险，不建议。

## 设计

### 1. 模板定义与版本

- 模板 schema 从 v1 升至 v2。`WorkflowFieldDefinition` 增加 `visible` 和可空的 `binding`；字段仍有稳定 `key`、`label`、`type`、`required`、`options`。
- 支持控件：`TEXT`、`TEXTAREA`、`NUMBER`、`RADIO`、`SINGLE_SELECT`、`MULTI_SELECT`、`PERSON`、`PERSON_MULTI`、`DATE`、`DATE_RANGE`、`ATTACHMENT`。
- `binding` 仅允许固定白名单：`project.description`、`project.priority`、`project.projectLevel`、`project.schedule`、`project.businessLine`、`project.projectManager`、`project.projectMembers`、`project.followers`。绑定字段仍使用项目现有数据/API，不将值复制到节点字段表。
- 固定绑定与控件类型对应为：description→TEXTAREA，priority→RADIO，projectLevel→SINGLE_SELECT，schedule→DATE_RANGE，businessLine→带组织树数据源的 SINGLE_SELECT，projectManager→PERSON，projectMembers/followers→PERSON_MULTI。优先级、等级、组织树和人员候选项由现有领域数据源提供，不写入自由选项配置。
- 项目绑定决定字段控件和数据源，避免把数字优先级错误存成文本或把组织架构选择误存为自由选项。绑定字段可配置显示名、显示/隐藏、必填与顺序；其控件类型和数据源由绑定决定。需要完全自定义控件时，新增不绑定的字段。
- 非绑定字段的控件类型、选项、显示名、可见性、必填和顺序均可编辑。选项仅适用于单选/下拉/多选；隐藏字段不得同时为必填。内部 key 生成后不可编辑，避免已有值和附件关联失效。
- 节点增加 `contentOrder`，按顺序引用 `fields` 表单区和 `component:<key>` 业务工作台。普通 v2 模板将绑定字段与自定义字段放在同一个 `fields` 槽；区内字段仍独立编辑、渲染和拖动排序。仅 v1 迁移可增加兼容槽 `legacy-custom-fields`，以保留旧版自定义字段在工作台之后的位置（详见下文）。节点本身继续按顺序拖动。分支/条件路由不在本次范围。
- v2 的 `contentOrder` 是节点内容顺序与可配置业务组件的唯一来源；v2 JSON 不重复保存旧版 `components`、`projectBasicInfo` 或 `projectBasicInfoFields`。后端对现有运行时 DTO 派生 `components` 列表，确保既有工作台挂载条件继续工作；v1 JSON 保持旧字段原样读取。
- 节点负责人、节点排期、任务看板固定存在，不进入可编辑字段或可删除工作台列表。其他当前工作台组件继续可配置、排序和复用。

### 2. 旧定义兼容

- 后端接受旧 schema v1 与新 schema v2。旧的 `projectBasicInfo` / `projectBasicInfoFields` 保留为兼容数据，不被新版本写入。
- 前端编辑器读取 v1 时，通过纯函数适配为 v2，并只保留一个字段定义数组：旧项目资料字段生成绑定字段，项目绑定 key 对原自定义 key 做 collision-safe 生成；原自定义字段 key、类型、选项和业务工作台保持不变，旧版自定义字段默认可见。若 v1 包含项目资料字段，`project-basic-info` 在内容顺序中转成旧位置的 `fields`；若包含旧自定义字段，则在旧工作台之后追加迁移专用 `legacy-custom-fields`。此标记存在时，`fields` 仅渲染绑定字段，兼容槽仅渲染未绑定字段；没有该标记的普通 v2 `fields` 槽渲染全部字段。定义和值都不复制。
- 适配只改变编辑器内存模型。明确保存才创建/更新草稿，发布生成新版本；已发布 JSON 和项目绑定版本不原地改写。
- 老项目仍按所绑定的 v1 版本读取详情和校验；新 v2 项目仍绑定不可变发布版本。更改默认模板只影响之后创建的项目；新建项目的模板默认带出且仍可切换。
- 不新增数据库迁移。原生字段沿用项目记录、成员和关注人关联；自定义字段和附件沿用节点字段值/附件表及乐观锁版本。

### 3. 配置界面

- 保留模板库、项目类型、默认模板、版本发布、顺序流程画布和节点名称/说明/交付物/角色设置。
- 选中节点后，画布明确分成固定区（负责人、排期）、可配置内容区、固定任务看板区。可配置内容区展示字段卡片与现有业务工作台卡片。
- 左侧组件库包括所有通用字段控件、可选的项目原生字段以及当前已存在的可复用业务工作台。拖入/添加后可编辑；字段卡片可拖动重排、隐藏或删除；业务工作台可排序或移除。固定模块不可拖出或删除。
- 字段属性面板按字段类型展示配置：单选/下拉/多选编辑选项；人员、日期、附件不显示无关选项；项目绑定字段展示绑定目标和控件来源。
- 节点预览和模板预览使用同一 schema，能看到字段类型、选项、必填状态、内容顺序及固定模块；`legacy-custom-fields` 使用独立的人类可读翻译名并按其 token 位置显示。

### 4. 运行时与数据流

- 项目详情页按 `contentOrder` 排列字段区及现有业务工作台。字段区中每个可见字段独立渲染。绑定字段通过已有项目资料表单和更新 API 保存；无绑定字段通过现有节点字段 API 保存，并继续支持附件及乐观锁。
- 兼容槽与 `fields` 共用唯一字段定义数组和节点值存储；跨节点、离页、完成和生命周期保存都 flush/save 两个实际渲染的槽。`profileContainer` 点击外侧检测只锚定项目绑定字段容器，不随旧自定义字段槽移动。
- 所有字段按配置显示；只有可见且必填字段阻止节点完成。前端即时提示，后端完成节点前再次校验，客户端绕过不能跳过必填约束。
- 无字段定义的 v2 节点允许空 `contentOrder`；字段槽必须与定义相符，未知/null 顺序项返回正常 schema 校验错误。空日期范围 `[]` 可作为草稿值保存，但必填范围在完成节点时仍算缺失。
- 后端只允许节点自定义字段 API 写入未绑定字段。人员字段校验项目成员权限；多人员字段逐个校验；附件仍校验归属项目、节点和字段。
- 业务工作台既有 API 和行为不变，仅按新内容顺序调整位置。固定负责人、排期、任务看板的节点生命周期逻辑保持不变。

## 非目标

- 不做条件分支、并行节点、审批流引擎、嵌套表单/任意布局网格。
- 不更换原生项目数据模型，不将项目字段迁入节点字段值表。
- 不自动覆盖已发布模板，不自动把现存项目升级到新模板版本。

## 验收标准

1. 可视化地添加、编辑、隐藏、删除并拖动字段；可新增/排序/移除当前已有业务工作台；节点可新增、编辑、排序、删除（至少保留一个）。
2. 通过 v1 适配，现有九阶段流程的节点、项目资料字段、业务工作台和既存字段值/附件关系保持完整；绑定字段留在旧项目资料位置，未绑定字段仍位于旧工作台之后；保存形成 v2 草稿，不改变旧发布版本。
3. 项目详情能按配置展示单行/多行文本、数字、单选、下拉、多选、人员/多人、日期/日期范围和附件；项目绑定字段更新原项目资料，无绑定字段更新节点字段值。
4. 必填与类型校验在前后端一致；隐藏字段不阻止完成；项目绑定字段与现有项目权限规则一致。
5. 负责人、节点排期、任务看板不可移除；默认模板仍按项目类型预选，创建者可切换；已有项目继续使用原绑定版本。
6. 前端测试、类型检查和构建通过；后端工作流与节点字段相关测试及完整测试通过；关键编辑、保存、发布和旧定义兼容路径通过浏览器验证。

## 已知约束与风险控制

- 字段删除不删除旧版项目中的值或附件；项目版本不可变，因此旧项目仍可读取原数据。新版本只允许访问其定义中声明的 key。
- schema 版本转换必须可重复、无副作用；重复加载 v2 不得重复生成字段或内容项。
- 项目绑定字段由后端白名单限制并要求类型匹配；选项源由现有项目数据源决定，不能由浏览器任意改写。
- 发布前不自动设置默认模板；操作者仍通过现有“设为默认”显式操作。
