# PMS Plane + Taiga 视觉与交互重构设计

## 目标

在不改变现有 API、路由、权限计算、数据模型和业务状态机的前提下，建立一套更接近 Plane 工作台效率与 Taiga 敏捷协作体验的 PMS 视觉和交互基线，并按页面逐步迁移。

## 参考边界

- Plane（<https://github.com/makeplane/plane>）：参考上下文导航、紧凑列表、筛选工具栏、项目/Issue 的上下文编辑和快捷反馈。
- Taiga（<https://github.com/taigaio/taiga-front>）：参考 Backlog → Sprint → 看板层次、卡片信息密度、拖拽反馈和敏捷协作状态。
- 只借鉴公开可见的交互模式和信息架构，不复制代码、图标、素材或受许可证约束的实现。

## 不变量与约束

1. 前端不新增业务字段，不修改接口语义，不把视觉状态当成业务状态。
2. 组织负责人、员工主归属、兼职归属和项目归属继续保持独立关系。
3. 后端仍是权限、数据范围和状态机的最终来源；前端只负责展示 `permissions` 和请求状态。
4. 邮箱是账号核心身份，人员标签继续遵循中文名/英文名可选、缺失回退邮箱的规则。
5. 所有新增视觉值必须先进入 `--pms-*` 语义令牌，再被组件使用；禁止在业务页用 `!important` 或魔法值掩盖共享契约。
6. 桌面端和窄屏均须验证，页面本身不能产生无意横向溢出；表格、画布和看板只能在自己的容器内滚动或平移。

## 目标体验

### 工作台壳层

- 顶栏、侧栏和内容区层级清楚，当前页面和所属大页签始终可辨识。
- 研发管理与配置管理作为一级分组，项目管理和治理页面作为二级入口；使用手册保持独立并位于导航底部。
- 全局搜索、通知、语言切换和用户菜单不挤压主要内容，在窄屏转为可触达的工具入口。
- 每个按钮、输入框、下拉框、日期选择器和标签拥有默认、Hover、Focus、Loading、Disabled、Error 状态。

### 项目工作流

- 项目列表优先展示项目名称、业务线路径、项目经理、状态、优先级、总体进度、任务/成员数量和周期。
- 项目详情按“项目头部 → 流程 → 当前节点 → 基本信息 → 任务看板 → 协作”组织上下文。
- 看板卡片保持稳定高度，Hover 只增强边框/阴影并展示操作，不改变列布局。
- 节点负责人和节点排期同排；业务线选择展示完整路径并可带出负责人候选；所有人员选择器使用统一标签。

### 企业治理

- 组织架构使用可平移、可缩放的画布；节点连接线、负责人和组织类型始终可见。
- 用户、角色、导入和审计页面共享相同的查询工具栏、表格、状态和危险操作反馈。
- 数据范围以中文解释为主，英文编码以小号辅助信息呈现。

## 组件层次

1. **令牌层**：颜色、字号、间距、圆角、阴影、焦点环、动效和断点。
2. **工作台原语**：页面头部、工具栏、面板、表格、Tabs、状态、人员标签、组织路径、空/加载/错误状态。
3. **页面模式**：项目列表、项目详情、看板、组织画布、权限表格、导入向导、反馈队列、使用手册。

组件优先通过现有 `src/components` 和 `src/styles` 扩展；页面只保留自身布局和业务编排。

## 页面迁移顺序

1. 视觉基线与令牌/原语。
2. 应用壳层和导航。
3. 项目列表与项目详情。
4. 组织架构、人员与权限、角色、导入和审计。
5. 工作台、反馈中心和使用手册。
6. 桌面/移动端视觉回归、可访问性和文档固化。

## 验收标准

- `pnpm test`、`pnpm typecheck` 和 `pnpm build` 均通过。
- Playwright 或浏览器验收覆盖项目列表、项目详情、组织画布、权限页面和使用手册。
- 至少检查 1440px、1280px、768px 和 390px 视口。
- 每期更新 `docs/frontend-design-system.md`、`docs/design-logic.md` 和 `design-qa.md`，记录已完成项和有意偏差。
- 视觉回归不能引入 API 请求变化、权限绕过或业务数据改变。
