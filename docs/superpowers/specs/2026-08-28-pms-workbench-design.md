# PMS 工作台与研发管理导航设计

## 目标

将侧边栏从“项目列表入口 + 配置入口”调整为清晰的业务域导航，并新增可用的工作台，让用户登录后首先看到与自己相关的项目、任务和动态。此次改造只增加工作台展示能力和导航层级，不改变现有项目、任务、成员、里程碑或权限规则。

## 导航结构

```text
工作台                         /dashboard
研发管理                       可展开分组
  项目管理                     /projects
配置管理                       可展开分组
  人员与权限                   /admin/users
  组织架构                     /admin/org
  角色管理                     /admin/roles
  批量导入                     /admin/import
  审计日志                     /admin/audit
```

“研发管理”是承载研发流程的业务域，当前先提供“项目管理”，后续可继续加入需求、计划、缺陷、测试、版本和看板。配置管理继续保留现有权限过滤；两个分组均支持展开/收起，当前路由的分组和子项保持高亮。

## 工作台信息架构

工作台路由为 `/dashboard`，页面标题为“工作台”，副标题为“我的工作”。首屏按以下顺序展示：

1. **工作概览**：待处理任务、进行中任务、即将到期、我参与的项目四项指标。
2. **我的任务**：按待办、进行中、已完成展示任务；每项包含任务名称、项目名称、负责人、优先级和截止日期，支持进入项目详情。
3. **项目进展**：展示当前用户可见且参与的项目，包含项目名称、业务线、项目经理、进度和周期，支持进入项目详情。
4. **最近动态**：展示与当前用户相关的项目动态或审计事件；接口暂不可提供时显示明确的空状态，不伪造业务数据。

数据优先复用现有项目分页、项目详情、任务和动态接口。由于当前后端没有跨项目“我的任务”聚合接口，第一版在前端按当前用户可见项目加载并聚合，限制请求数量并对单项目失败进行降级；不新增数据库表和后端业务规则。当前用户从 Pinia 用户状态获取，人员匹配使用用户 ID，避免仅按显示名称匹配。

## 响应式与视觉

- 继续复用 `fs-insight.css` 中的冷灰背景、白色面板、深蓝主色和低阴影令牌。
- 桌面端采用“概览四列 + 任务/项目两列 + 动态”布局，卡片使用统一的面板和状态标签。
- 760px 以下自动变为单列；任务和项目列表允许内容换行，不产生页面级横向溢出。
- 空数据、加载中和请求失败均提供明确的中文状态提示与重试入口。

## 文件边界

- `src/layout/Index.vue`：研发管理分组、工作台路由入口、活动状态与展开收起。
- `src/router/index.ts`：新增 `/dashboard` 路由。
- `src/views/workbench/index.vue`：工作台页面与数据聚合。
- `src/views/workbench/workbench.ts`：纯函数数据转换与指标计算，便于测试。
- `src/views/workbench/workbench.test.mjs`：工作台指标、过滤、排序和降级逻辑测试。
- `src/styles/fs-insight.css`：仅补充工作台响应式布局样式。

## 验收标准

- 登录后访问 `/dashboard` 能渲染有意义的工作台，不再将工作台指向项目列表。
- “研发管理”可展开，子项“项目管理”跳转 `/projects`；“配置管理”原有子项和权限行为不变。
- 项目详情入口、项目编辑/删除、权限校验等既有行为保持不变。
- 工作台在桌面和 390px 窄屏下无页面级横向溢出，加载失败有可读提示。
- 前端静态测试、类型检查、生产构建和浏览器交互回归全部通过。
