# 企业项目看板一期设计

## 已确认范围

面向业务单元负责人和公司高管，升级现有企业项目总览，支持组织筛选、项目状态/等级/健康度分析和项目下钻。侧栏新增「经营分析」分类，原「研发管理」中的看板入口迁至「经营分析 → 企业项目看板」。保留 `/projects/dashboard` 和 `/projects/:id` 链接。部门及业务线通过组织树筛选（包含下级组织），个人指标和部门专项看板留待后续。

依据用户提供的《项目管理数字化》4.1、4.5 指标与当前系统数据，优先提供能解释、能下钻的当前快照。用户已确认范围、名称、原页迁移，并要求直接实施。

## 信息结构与交互

页面采用现有 PMS 冷灰背景、白色面板和蓝色主操作令牌。标题旁显示统计范围、更新时刻和刷新入口；筛选区提供组织、项目等级、状态、健康度和项目搜索。

首层展示项目总数、待开始、进行中、已完成、已终止及重点关注数量。第二层展示健康分布、S/A/B/C 项目结构、组织对比。第三层展示需关注项目和近期节点里程碑；最后是可分页、可筛选的项目清单。图表分组、状态卡和关注入口使用真实按钮，点击联动筛选并提供清除入口。

项目清单包括项目名称/编码、等级、组织、项目经理、状态、当前节点、节点完成度、计划截止日期和健康信号。点击项目名进入现有详情，返回保留筛选。项目分析抽屉可展示该项目可用的故事状态、验收缺陷和风险/排期解释，并提供进入详情入口。

数据完整度和未接入指标集中在「指标口径」抽屉，避免大面积空图表。任何未知数值使用 `—` 与原因，明确区分无数据和真实 0。桌面分析区双栏/三栏；窄屏单列，表格只在自身容器横向滚动。

## 统计口径

全部数字只包含当前账号可读且未删除的项目。组织包含所选组织及其下级；等级、状态、健康度、关键词对图表和项目清单使用同一项目集合。返回数据代表当前快照，不绘制没有历史来源的趋势。

| 指标 | 一期规则 |
| --- | --- |
| 项目生命周期 | 后端 ACTIVE（含历史 0/空）、COMPLETED、TERMINATED；删除排除。系统没有独立「已驳回」状态，不由终止或流程回滚推断驳回。 |
| 待开始/进行中 | ACTIVE 项目有节点且全部未开始则为待开始；任一节点进行中或已完成则为进行中；无有效节点为阶段待补充。项目状态 0 不单独代表待开始。 |
| 项目等级 | 沿用项目等级枚举：3=S、2=A、1=B、0=C；缺失归入未分级。 |
| 项目进度 | 使用项目 DTO 的节点完成度；明确标注口径，不宣称为故事交付完成率。 |
| 健康度 | 计划时间线按起止日期线性估算，与节点完成度比较。落后 8 个百分点预警，15 个百分点严重。逾期未完成节点、项目超期、未关闭高风险为严重；未关闭中风险为预警。 |
| 里程碑 | 使用现有流程节点排期作为「节点里程碑」；不重新引入已退出当前流程的旧里程碑入口或旧数据。 |
| 数据完整度 | 有已知严重/预警信号则优先提示，同时列出缺项；没有预警但缺有效项目排期、节点排期或风险登记组件时显示「待评估」，不判定健康。 |
| 风险 | 只统计当前项目工作流启用的风险组件中 OPEN 风险。未配置为未知，已配置且无风险为 0。 |
| 故事与验收缺陷 | 当前配置中开发故事的状态、逾期未完成故事和故事点可汇总；验收缺陷仅称「验收缺陷」，不冒充线上故障。 |

待开始等待天数缺少可靠入态时间，暂不套用文档的 5–7/7–10 天灯色。已完成评分缺少数值字段，暂不套用 60/80 分灯色。当前统一健康度与这些指标分开解释。

## 数据缺口

平均实际交付周期/趋势需要可靠实际启动与完成事件；项目评分/满意度需要结构化评分；P0/P1 线上故障需要生产故障台账；资源利用率与战略匹配度需要投入人天和可用人天。现有人员、角色、故事点都不能直接替代人天。上述指标在口径说明中标为「待接入」，一期不新增这些独立业务子系统。需求 WIP 历史、缺陷日留存及个人绩效指标不在本期范围。

## 前后端边界

新增只读 `GET /projects/board?orgUnitId=` 聚合端点，使用 `project:read` 并复用项目列表的数据可见范围和组织下级筛选。后端批量加载项目及当前工作流节点/风险/故事/验收缺陷，负责健康与数据可用性判定；请求数量不随项目个数线性增长。

响应为 `asOfDate`、`generatedAt`、`allCompanyScope` 和 `projects`。每项包含 `project`（现有 ProjectDTO）、`phase`、`health`、`expectedProgress`、`progressVariance`、`overdueDays`、`overdueNodeCount`、`openRiskCount`、`highRiskCount`、`mediumRiskCount`、`riskDataState`、`nodeDataState`、`dataIssues`、`nextNode`、`storySummary`、`acceptanceSummary`。未配置业务组件的汇总为 null。

前端按组织变化重新取聚合数据，其余筛选与图表在同一快照上计算，分页只影响清单，不改变统计分母。刷新/筛选请求使用序号或取消机制，防止旧响应覆盖新条件。后端失败显示可重试错误；已有数据刷新失败可保留并标注过期，不能标为新条件下结果。

不提升账号权限。无 `project:read` 时入口不可见且接口拒绝；组织筛选不能扩大原数据可见边界。项目详情沿用原权限。

## 验证与交付

后端测试覆盖权限范围、组织下级、真实零/未配置、阶段判断、健康阈值、组件删去后的旧数据隔离及空集合。前端测试覆盖筛选、汇总分母、排序、空集合与未知数值。运行类型检查、生产构建与现有回归；浏览器验证导航迁移、图表联动、组织切换、抽屉、项目下钻及桌面/窄屏无页面溢出。

实际服务由这两个 worktree 的 Docker Compose 运行，交付时构建并更新前后端服务，不更换数据库卷。当前阶段不合并主分支。
