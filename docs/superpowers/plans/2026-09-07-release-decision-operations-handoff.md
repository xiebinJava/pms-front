# 发布决策与运营交接节点实施计划

## 目标

把已确认的轻量版 demo 落到真实项目详情页：在 `release` 节点提供发布信息、上线检查、发布决策和运营交接，并通过后端校验后才能完成节点。

## 设计边界

- 发布信息只维护当前采用的一个版本：版本号、发布窗口、发布类型。
- 上线检查保留 5 项，逐项人工确认；任务完成状态不替代人工检查。
- 发布决策只记录结果和说明，不引入独立审批流。
- 运营交接保留交接说明、发布后观察事项、值班与应急联系人。
- 页面只保留节点头部一个“完成节点”入口；完成节点由后端再次校验。
- 任务看板在节点详情中仅展示关联任务数量与状态摘要，继续使用现有任务模块。

## 后端

1. 新增 `project_node_release_baseline` 表、实体、Mapper、请求/响应 DTO。
2. 新增 release 工作台 GET/PUT 接口和 `NodeReleaseService`。
3. 保存时校验字段长度、发布窗口顺序和枚举值，并使用乐观锁。
4. 完成节点时校验发布信息、5 项检查、`APPROVED` 决策和三项交接信息。
5. 新增审计动作，接入 `NodeService.complete`。

## 前端

1. 新增 release API、类型、完成条件纯函数和工作台组件。
2. 在项目详情页按 `activeNode.nodeKey === 'release'` 挂载工作台。
3. 工作台按 demo 的紧凑结构展示，并向父页面同步完成条件。
4. 保留父页面统一的“完成节点”按钮，按钮状态仅作提示，后端仍是最终校验。

## 验证

- 先运行新增的前后端单元/静态结构测试，确保失败条件覆盖完成条件。
- 执行后端 Maven 测试与前端 lint/type/build/test 命令。
- 启动前后端后用 Playwright 验证 release 节点加载、保存、未满足条件时不可完成、满足条件后可完成，以及移动端无横向溢出。
